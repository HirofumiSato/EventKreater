## イベント主催者・参加者向け 権限管理＆段階的会員基盤（Progressive Membership & Lean RBAC）

## 1. システム概要と認可マトリクス

### 1.1. システムの位置づけ
本ドキュメントは、AIによる自動実装および後続のコード生成を目的とし、イベント管理における「匿名参加」「段階的アカウント昇格」「共同幹事招待」「排他編集ロック」のシステム境界と仕様を定義するものである。会員の一意性（確認済み電話番号、メールと Google の重複防止）は、共通編 `docs/overall_system_requirements_common.md` 第4.3節を正とする。

### 1.2. アクター定義
* **ゲスト参加者（Guest Participant）:** 会員登録を行わず、イベントページから出欠登録を行ったユーザー。
* **会員参加者（Registered Member）:** アカウントを保持し、過去に参加したイベントをマイページで一覧照会できるユーザー。
* **ゲスト幹事（Guest Organizer）:** 会員登録をスキップしてイベントを作成した主催者（ブラウザの暗号化トークンで管理）。
* **会員幹事（Registered Organizer）:** アカウントを保持し、過去の主催イベント一覧の閲覧およびワンクリック複製が可能な主催者。
* **共同幹事（Co-Organizer）:** 招待リンク経由で幹事権限を付与された追加主催者。

### 1.3. 権限マトリクス（Role-Based Access Control）

| 操作対象 / アクション | ゲスト参加者 | 会員参加者 | ゲスト幹事 | 会員幹事 / 共同幹事 | 備考 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **イベントページの閲覧** | ○ | ○ | ○ | ○ | 一般公開 |
| **出欠の登録** | ○ | ○ | ○ | ○ | 名前＋出欠ステータス |
| **自身の回答確認・変更** | ○ (同端末のみ) | ○ (全端末) | ○ | ○ | ゲストはCookie/Storage識別 |
| **参加者一覧の閲覧** | × | × | ○ | ○ | 幹事のみに完全秘匿 |
| **イベント情報の編集** | × | × | ○ (ロック時) | ○ (ロック時) | 単一排他ロックが必要 |
| **共同幹事の招待URL発行** | × | × | ○ | ○ | 招待トークン生成 |
| **主催イベント一覧の照会** | × | × | × | ○ | 会員登録が必須 |
| **過去イベントの複製作成** | × | × | × | ○ | 会員登録が必須 |
| **参加イベント一覧の照会** | × | ○ | × | ○ | 会員登録が必須 |

## 3. 機能要件詳細（Functional Requirements）

### FR-01: イベント作成とプログレッシブ幹事登録
* **概要:** 幹事はアカウント未登録のままでもイベントを立ち上げ可能とする。
* **仕様:**
  1. タイトル、日時、場所、概要を入力して「作成」を押下。
  2. 会員登録モーダルを表示し、「アカウントを作成してイベントを管理する（推奨）」または「登録せずに今すぐ作成（スキップ）」を選択させる。
  3. **スキップ選択時:**
     * サーバー側でセキュアな管理用ケイパビリティURL（例: `/manage/events/{event_id}?token={organizer_token}`）を生成。
     * 幹事ブラウザのCookie（HttpOnly）に幹事セッショントークンを付与。
     * 画面上に「この管理URLを保存してください。会員登録すればいつでも一覧から確認できます」のバナーを常時表示。
  4. **登録選択時:**
     * Googleアカウントでのサインインで即時会員化し、`organizer_user_id` とイベントを紐付ける。
     * 会員の識別子は Google の `sub` とする。表示名とメールアドレスは Google アカウントの値を初期値にする。パスワードは作らない。
     * パスキー、LINE、マジックリンクは追加手段であり、本会員登録の必須条件は Googleサインインである。

### FR-02: ゲスト参加登録と端末自動照会（連絡先入力なし）
* **概要:** 参加者はメールアドレス不要で、名前と出欠のみで登録し、同端末であれば再訪時に回答状態を確認できる。
* **仕様:**
  1. 入力項目は「参加者名（必須）」「出欠ステータス（参加/不参加/未定・必須）」「コメント（任意）」のみ。
  2. 登録完了時、バックエンドは `participant_id` と紐付く署名付き `response_token` を生成し、ブラウザの `Cookie`（SameSite=Lax）および `LocalStorage` に格納。
  3. ユーザーが同一イベントURLへ再アクセスした際、クライアントから送信された `response_token` を検証。
  4. 検証成功時、フォームを「あなたの回答状態（変更可能）」表示に切り替える。
  5. 画面下部に「会員登録すると、参加したイベントが一覧で残せます」という導線（Account Hydration Prompt）を表示。

### FR-03: 参加者一覧の厳格な秘匿制御
* **概要:** 参加者一覧データは幹事のみに公開し、参加者には一切レスポンスしない。
* **仕様:**
  1. 一般公開用イベント詳細API（`GET /api/public/events/{id}`）には参加者氏名リストを含めない（参加者数・カウントのみ返却可能）。
  2. 参加者一覧取得API（`GET /api/organizer/events/{id}/participants`）は、幹事セッショントークンまたは認証済み幹事セッションの検証を必須とし、認可失敗時は `403 Forbidden` を返す。

### FR-04: 共同幹事の招待方式
* **概要:** 既存幹事が招待リンクを発行し、他の幹事に管理権限を委譲・共有する。
* **仕様:**
  1. 幹事ダッシュボードから「共同幹事の招待リンクを発行」を押下。
  2. 暗号学的に推測不可能なワンタイムまたは有効期限付きの招待用URI（例: `/events/{id}/join-organizer?invite_code={secure_random}`）を発行。
  3. 別のユーザーがそのURLを踏んだ場合：
     * 会員ユーザーであれば、そのアカウントを該当イベントの共同幹事（`EventOrganizer` レコード）に追加。
     * 未登録ユーザーであれば、ブラウザに幹事権限Cookieを付与しつつ、会員登録を促す。

### FR-05: 悲観的リースロック（同時編集不可・引き継ぎUX）
* **概要:** 複数幹事による同時編集によるデッドロック・上書き事故を防止する。
* **仕様:**
  1. **ロック獲得 (`POST /api/organizer/events/{id}/lock`):**
     * 編集画面遷移時にロック取得を試行。ロック有効期限（TTL）は180秒。
     * 成功時: ロックトークンを返却し、画面内の入力項目を活性化。
     * 失敗時（他者が保持中）: `409 Conflict` と共に「保持者名（または端末識別子）」「残り有効秒数」を返却。画面を閲覧専用（Read-Only）とし、「編集権を引き継ぐ」ボタンを表示。
  2. **ハートビート (`PUT /api/organizer/events/{id}/lock`):**
     * 編集画面を開いている間、フロントエンドから30秒間隔でTTLを180秒に延長するリクエストを自動送信。
  3. **強制引き継ぎ (`POST /api/organizer/events/{id}/lock/takeover`):**
     * 「編集権を引き継ぐ」押下時、既存のロックを失効させ、リクエスト送信者に新たなロックを付与。
     * 旧ロック保持者のハートビートは次回送信時に `401/409` で拒否され、画面上に「他の幹事が編集権を引き継ぎました。編集内容は保存されません」とダイアログを表示してRead-Only化。
  4. **ロック解放 (`DELETE /api/organizer/events/{id}/lock`):**
     * イベント保存完了時、または「キャンセル」押下による画面離脱時に明示的に解放。

### FR-06: 過去イベント一覧とワンクリック複製
* **概要:** 登録済み幹事は過去のイベント資産を再利用して新規イベントを作成できる。
* **仕様:**
  1. 幹事マイページにて、自身が主催・共同主催したイベント一覧を表示。
  2. 各イベントに「このイベントをコピーして新規作成」アクションを配置。
  3. 押下時、タイトル（「〇〇のコピー」）、概要、開催場所等の設定項目を引き継いだ状態で新規作成フォームを展開（開催日時は空白、参加者リスト・出欠データは一切引き継がない）。

### FR-07: 会員登録とアカウント昇格（Account Hydration）
* **概要:** 本会員登録は Googleアカウントでのサインインとする。ゲスト状態で参加・作成した履歴を、サインインしたタイミングで正式アカウントに統合する。
* **仕様:**
  1. 会員登録画面とログイン画面に「Googleでサインイン」を置き、Google の `sub` で会員を作成または照合する。同じ `sub` の再サインインは同一会員とする。
  2. 表示名とメールアドレスは Google アカウントの値を初期値として保存する。パスワードは保持しない。
  3. ゲスト参加者がサインインした場合、ローカルストレージ/Cookie内の `response_token` 群をバックエンドへ送信する。
  4. 当該トークンに紐づく過去の `Participant` レコードの `user_id` をその会員IDで更新する。
  5. 以降、会員マイページ（`GET /api/member/attended-events`）にて過去参加イベントが一元表示される。
  6. ゲスト幹事がサインインした場合も同様に、保持している幹事トークンをユーザーIDへ昇格・バインドする。

## 4. 非機能要件（Non-Functional Requirements）

### 4.1. セキュリティ要件
* **Capability Token のエントロピー:** 招待コードや端末識別トークンには、推測不可能な暗号学的擬似乱数（CSPRNG: 128bit以上、NanoID 21文字またはUUIDv4）を使用。
* **Cookie セキュリティ:** トークンをCookieで保持する場合、`HttpOnly=true`, `Secure=true`, `SameSite=Lax` を必須とする。
* **マスアサインメント脆弱性防止:** 参加者の登録APIで、幹事権限フラグや他イベントIDの書き換えができないようDTOバリデーションを厳格化。

### 4.2. データ整合性と可用性
* **オフライントランザクション整合性:** 排他ロック情報はインメモリ（Redis等）またはDBの `EditLock` テーブルでアトミックに制御し、DBトランザクション（`SELECT FOR UPDATE`）で二重ロック取得を完全に遮断。
* **TTL自動失効:** ブラウザクラッシュやネットワーク切断による放置ロックは、DBのタイムスタンプ比較（`locked_at + 180s < NOW()`）によりバックグラウンドジョブなしで自動失効判定。

## 6. APIインターフェース仕様（REST/JSON）

### 6.1. 公開・参加者向けエンドポイント
* `GET /api/public/events/{id}`
  * イベント詳細情報（タイトル・日時・場所・概要）を取得。※参加者一覧は返却しない。
* `POST /api/public/events/{id}/rsvp`
  * 出欠登録。`{ name, status, comment }` を送信。
  * レスポンス: `{ participant_id, status }` ＋ `Set-Cookie: rsvp_token={token}` 発行。
* `GET /api/public/events/{id}/my-rsvp`
  * 保持しているCookieまたはヘッダーのトークンから、自身の回答ステータスを取得。
* `PUT /api/public/events/{id}/my-rsvp`
  * 自身の回答ステータス・名前・コメントを変更。

### 6.2. 幹事専用エンドポイント
* `GET /api/organizer/events/{id}/participants`
  * 参加者一覧（全員の氏名、ステータス、コメント、登録日時）を取得。幹事認証必須。
* `POST /api/organizer/events/{id}/lock`
  * 編集ロック取得。
  * 成功: `200 OK { lock_token, expires_at }`
  * 競合: `409 Conflict { message, holder_name, expires_at }`
* `PUT /api/organizer/events/{id}/lock`
  * ロック延長（ハートビート）。`{ lock_token }` を送信してTTLを再設定。
* `POST /api/organizer/events/{id}/lock/takeover`
  * ロック強制引き継ぎ。既存のロックを無効化し新規ロックトークンを発行。
* `DELETE /api/organizer/events/{id}/lock`
  * ロック明示解放。
* `PUT /api/organizer/events/{id}`
  * イベント情報更新。ヘッダーに `X-Lock-Token` を付与し、有効なロック保持者のみ許可。
* `POST /api/organizer/events/{id}/invite`
  * 共同幹事の招待コード生成。

### 6.3. 会員・マイページエンドポイント
* `POST /api/member/hydrate`
  * ゲスト時の端末トークン（参加トークン群・幹事トークン群）をアカウントへ一括紐付け。
* `GET /api/member/organized-events`
  * 主催（または共同主催）したイベント一覧を取得。
* `POST /api/member/organized-events/{id}/clone`
  * 指定した過去イベントの設定値をベースに、新規イベントを下書き作成。
* `GET /api/member/attended-events`
  * 過去に参加登録したイベント一覧を取得。
