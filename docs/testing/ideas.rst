何を自動で確かめるか
======================

読む順の 2 番です。前は :doc:`index`、次は :doc:`design` です。

自動実行の目的は、利用枠、決済イベントの反映、認証、排他ロック、入力の拒否が、仕様の数と HTTP ステータスのまま手元で再現できることです。同じ入力からは同じ結果になり、ブラウザも有料 API も要りません。

自動化する条件
----------------

次の三つが揃う振る舞いを、自動テストにします。

* 期待結果が、仕様の数値、HTTP ステータス、エラーコード、メッセージで決まっている。
* 画面を眺めただけでは見落としやすい。金額、権限、ロック、同じ決済イベントの再送がこれに当たります。
* Stripe、Google、OpenAI、チラシ API への実通信なしで再現できる。

三つが揃うものは :doc:`first-cases` に具体的なケースとして書きます。見た目の良し悪しや、外部サイトの画面遷移は、下の「人手で確認するもの」に残します。

合格の定義
----------

合格は、収集されたテストが成功し、次の値が実装に合わせて緩んでいないことです。

* 無料枠は 2 回（``FREE_EVENT_LIMIT``）
* 上限到達は HTTP 402、``error`` は ``QUOTA_EXCEEDED``
* 単発は 299 円、月8回プランは 980 円、作り放題は 2,980 円（``SUBSCRIPTION_8_PRICE_JPY`` / ``SUBSCRIPTION_UNLIMITED_PRICE_JPY``）
* 排他編集ロックは期限を持たない
* 会員登録のパスワードは 8 文字以上
* Webhook は、署名が無い、または検証に失敗すると 400。同じイベント ID の再送は本体処理をしない
* 未登録の幹事が筆頭として持てるイベントは 1 件。2 件目は 403、``error`` は ``REGISTER_REQUIRED``
* 未登録の幹事が編集できるのは作成から 24 時間ちょうどまで。1 ミリ秒でも過ぎたら 403 ``REGISTER_REQUIRED``
* 名簿・リマインド・領収書・共同幹事の招待は、未登録では 403 ``REGISTER_REQUIRED``。401 にはしない
* 会員登録で引き継ぐと、無料枠は筆頭幹事の数だけ増える。ただし ``FREE_EVENT_LIMIT`` を超えない

失敗したテストは、期待値を下げて通しません。実装を直します。行が何割実行されたかは、合格条件にしません。

人手で確認するもの
------------------

次は :doc:`/local` の画面確認で人が見ます。Stripe の鍵と課金の境界は :doc:`/stripe` です。

* チラシのファーストビュー、Peek UI、Tailwind の間隔と色
* Stripe Checkout と Customer Portal の実画面
* Google サインイン
* 管理画面の一覧と検索

これらは結果が外部画面や目視に依存するため、既定の ``npm run check`` には入れません。

チラシ生成との分担
------------------

1080×1528 の描画、コントラスト、OpenAI を模したアダプターは、:doc:`/flyer/testing/index` の pytest が確認します。

Next.js 側が持つ範囲は次の二つです。

* ``toFlyerPayload`` が、チラシ API のフィールド名と雨天方針の日本語ラベルを組み立てること
* チラシ API の失敗を、422、429、接続失敗時の 502 に対応づけること

Pillow による文字描画の再試験は、この節の範囲外です。
