テスト計画
==========

この計画は、チラシ生成 API が仕様どおり動き、外部の有料 API に依存せずに繰り返し確認できることを目的にします。品質の合格は、文字が決まった枠に収まること、失敗の種類ごとに HTTP ステータスが決まっていること、画像生成の失敗でも利用者に空の失敗を返さないことです。

対象
----

.. list-table::
   :header-rows: 1
   :widths: 24 76

   * - 層
     - 確認すること
   * - ドメイン
     - 文字数、改行の除去、アクセント色と不透明度、例外の HTTP 対応
   * - レンダラー
     - 1080×1920 の JPEG、タイトル枠、コントラスト 4.5、高周波背景、外部 API を参照しないこと
   * - アダプター
     - キーの有無によるモック切替、構造化出力、DALL-E のリトライと静的背景、不正なダウンロード
   * - API 結合
     - 生成からダウンロード、422 / 429 / 503 / 500、存在しない ID
   * - ストレージ
     - 原子的な書き込み、TTL 削除、ディスク空きが少ないときの強制削除

対象外
------

次は自動テストの範囲に入れません。

* OpenAI への実通信。キーや課金、応答の揺らぎで結果が安定しないためです。
* ブラウザの見た目と Swagger のクリック操作。手順は :doc:`/flyer/swagger` で人が確認します。
* 同時アクセスの性能、月間の利用回数、印刷用の色空間。
* 特定の PC に日本語フォントが無い環境。テストは開発機のフォントが読めることを前提にします。

方針
----

* 外部 I/O はポートを差し替える。プロンプトエンジン、画像生成、レンダラーは ``create_app`` の引数で偽の実装にできます。
* 画像生成の待ち時間は本番の 25 秒を使わない。テストでは短い予算を注入します。
* 保存先は ``tmp_path`` とし、開発用の ``src/static/tmp`` を消しません。
* 合格条件の数値（コントラスト 4.5、タイトル幅 920、高さ 420、TTL 3600 秒）は緩めません。失敗したら実装を直します。
* 型は pytest とは別に ``mypy --strict src`` で見ます。テストコード自体は mypy の対象外です。

環境と実行
----------

Python 3.11 以上、プロジェクトルート、``requirements.txt`` を入れた状態です。

.. code-block:: powershell

   python -m pytest tests/ -v

開始条件は、依存のインストールが終わり、``src`` を import できることです。終了条件は、収集されたテストがすべて成功し、上の数値を変えて通していないことです。

リスク
------

* フォントのファイル名は OS ごとに違います。解決順を変えると、タイトル幅のテスト結果が変わります。
* ディスク空き容量の試験は ``disk_usage`` を差し替えます。実ディスクが 10% 未満の機械では、差し替え漏れがあると一時ファイルが消えます。
* レート制限はプロセス内のメモリです。テストごとにアプリを作り直し、回数を持ち越さないようにします。
