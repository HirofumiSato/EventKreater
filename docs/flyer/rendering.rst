文字合成
========

基準キャンバスは 1080×1528 px（A4 縦 210:297）です。背景が別サイズでも、中央を基準に覆うように拡大してからこのサイズへ切り出します。出力は品質 90 の JPEG です。

処理は 3 段だけです。背景を収める → 紙面の計画を組む（:mod:`src.adapters.renderer.poster`）→ 面と文字を描く。計画は画像もフォントも触らない純関数なので、目盛りが守られているかを画像なしで検証できます。

目盛り
------

「その枠に入る最大の字」を置くと、紙面ごとに文字サイズの関係が壊れて揃って見えません。文字サイズは比 1.25 の 11 段だけを使います。

.. code-block:: text

   17 / 22 / 27 / 34 / 42 / 53 / 66 / 83 / 104 / 130 / 163

左右の余白は 96 px、本文幅は 888 px です。縦位置はすべて 8 px の倍数に載せます。数値は :mod:`src.adapters.renderer.design` が持ちます。

.. list-table::
   :header-rows: 1
   :widths: 18 12 12 58

   * - スロット
     - サイズ
     - 行間
     - 内容
   * - eyebrow
     - 22
     - 24
     - 日付。字間 +4 px、差し色。`2026年11月14日（土）` のように年と曜日まで入れる（`YYYY-MM-DD` のまま焼かない）
   * - title
     - 42–163
     - 1.18
     - 催し名。墨
   * - rule
     - 2–6 px
     - ―
     - 見出しの下の差し色の罫線。96 / 888 / 240 px
   * - meta
     - 34
     - 40
     - 時刻。墨の補助色
   * - facts
     - 22 / 27（34）
     - 24 / 32
     - 会場・参加費・定員。ラベルと値を 1 px の罫線で区切る
   * - note
     - 17
     - 24
     - 雨天の扱い。墨の補助色。ピルは使わない

差し色を使うのは eyebrow の文字と見出し下の罫線だけです。明細のラベルは墨の補助色で、大きな文字に差し色は使いません。

配置
----

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - 配置
     - 積み方
   * - ``classic``
     - 見出しを上端、詳細を下端。写真の主役が真ん中に残る
   * - ``top_stack``
     - 見出しと詳細を続けて上端へ。下半分が空く
   * - ``center_stack``
     - 全体を中央へ。上下に余白が残る
   * - ``bottom_stack``
     - 全体を下端へ。上半分が空く

アンカーは :class:`src.adapters.renderer.layouts.StackSpec` が持ちます。

タイトルのフォントサイズ
------------------------

:func:`src.adapters.renderer.layout_calculator.fit_to_scale` が、目盛りの大きい段から順に試し、最初に収まった組み方を返します。上限は幅 888 px、高さは配置ごとの ``title_height``（最大 480 px）、3 行です。中間の値は作りません。

1 行に収まるタイトルは改行しません。収まらないときだけ、意味の区切りで行を分けます。区切りの候補は :func:`src.domain.title_composition.title_splits` が作り、助詞の直後・句読点の直後・末尾語（「夕べ」「セッション」など）の直前・文字種の変わり目・入力された空白を加点します。1 文字だけの行、小書き仮名から始まる行、句読点や閉じ括弧から始まる行は候補にしません。

同じ段で複数の切り方が収まるときは、行数が少ないほうを採ります。字間は 1 行のときだけ 6 px 開きます。行を分けたときに字間を足すと、意味の区切りの幅が残りません。

最終行が 2〜5 文字で、最長行の幅の 70% 未満のときは、その行だけを本文ブロックの右端へ揃えます（ぶら下げ）。「焚火とシチューの／夕べ」の右下配置がこれです。左揃えの紙面だけで使い、中央揃えでは行いません。

可読性
------

文字色と、その矩形の平均色から WCAG 2.1 の相対輝度とコントラスト比を計算します。通常文字の合格ラインは 4.5 です。下回るときは、黒や白の帯ではなく、紙の色（墨の面の紙面では面の色）を薄く重ねます。写真の上でも「紙が 1 枚かかっている」ように見え、角丸の板や黒いスクリムを避けられます。

面（帯・墨の面）は写真を透かして敷きます。既定の不透明度は ``design.SURFACE_ALPHA`` の 1 箇所が持ち、帯が 0.82、墨の面が 0.86 です。地が濃くて墨が 4.5:1 に届かないときだけ ``veil_alpha`` の値まで濃くし、透けていても読める範囲に収めます。

面の上の文字色は、面を敷いたあとの実色（透けた地との合成後の平均）を地として ``ensure_contrast`` で決め直します。面の外の写真の平均色で決めてはいけません。暗い写真の上では墨が白へ押し上げられ、明るい帯と同化します。面の上の罫線は 4.5:1 を狙わず、面の実色と墨を 24% で混ぜて「文字より弱く、地より強い」関係だけを保ちます。

矩形は (x, y, 幅, 高さ) と (x1, y1, x2, y2) を取り違えやすい場所です。判定には ``PosterSlot.area`` / ``PosterRule.area`` を使います。

差し色は地に対して 4.5:1 を満たすまで濃さを寄せます（``safe_accent``）。ネオ・ブルータリズムの黄（``#FFD84D``）や夜のスレートの藍（``#4F46E5``）は、そのままでは明るい紙に載せられません。

フォント
--------

テンプレートごとに明朝、ゴシック、太ゴシックを使い分けます。同梱フォントが無い環境では、Windows の Noto / 游ゴシック / メイリオ、macOS のヒラギノや AppleGothic、Linux の Noto Sans CJK を順に探します。どれも読めないときは :class:`src.domain.exceptions.FontRenderError` です。
