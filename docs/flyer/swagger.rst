Swagger UI の使い方
====================

Swagger UI は、起動中の API をブラウザのフォームから試す画面です。このプロジェクト専用に作った画面ではなく、FastAPI がルート定義から自動で出します。住所は http://127.0.0.1:8000/docs です。

サーバーが止まっていると、このページは開きません。先に :doc:`local_run` の手順で ``uvicorn`` を起動してください。ログインは不要です。

画面に並んでいるもの
--------------------

上から、この API の機能が帯になって並びます。色は操作の種類です。

* **GET** は、すでにあるものを取りにいきます。緑の帯です。
* **POST** は、データを送って処理を頼みます。青い帯です。

このアプリでは次の三つです。

* ``GET /health`` は死活確認です。
* ``POST /api/v1/flyers/generate`` はチラシの生成です。
* ``GET /api/v1/flyers/{flyer_id}`` は完成 JPEG の取得です。

帯の右端の三角を押すと、その機能が開きます。一番下の **Schemas** は、送る JSON と返る JSON の項目一覧です。試し打ちの前に、項目の意味を見る場所です。

死活確認を押してみる
--------------------

1. ``GET /health`` の帯を開く。
2. 右上の **Try it out** を押す。これで、読むだけの表示から実行できる状態に変わります。
3. **Execute** を押す。

少し下に、サーバーが返した内容が出ます。

* **Code** が ``200`` なら成功です。
* **Response body** が ``{"status":"ok"}`` なら、サーバーは要求を受けています。
* **Curl** は、同じ要求をコマンドで送るときの例です。使わなくて構いません。

チラシを 1 枚作る
------------------

1. ``POST /api/v1/flyers/generate`` の帯を開く。
2. **Try it out** を押す。
3. **Request body** の編集欄に、次を貼り付ける。欄に最初から例が入っているときは、一度消してから貼ります。

.. code-block:: json

   {
     "title": "ジャズの夜",
     "event_date": "2026年11月15日(日)",
     "event_time": "19:00〜22:00",
     "price": "3,000円",
     "location": "Jazz Bar MOON",
     "template_id": "style_1_bar_stylish"
   }

4. **Execute** を押す。キーが無いときのモックなら数秒、OpenAI を使うときは最大で約 25 秒かかります。そのあいだは Execute の近くが待ち状態になります。ページを閉じないでください。

成功すると Code は ``200`` です。Response body は次の形です。

.. code-block:: json

   {
     "status": "success",
     "generation_id": "ここにUUID",
     "image_url": "/api/v1/flyers/ここにUUID"
   }

``status`` が ``fallback_used`` でも、画像は作れています。背景の生成だけが予備の絵に切り替わった、という意味です。

画像をブラウザで見る
--------------------

Swagger の応答は JSON であり、画像そのものではありません。``image_url`` の値をコピーし、ブラウザのアドレスバーで ``http://127.0.0.1:8000`` のうしろにつなぎます。

例: ``image_url`` が ``/api/v1/flyers/8f1c...`` なら、開くアドレスは ``http://127.0.0.1:8000/api/v1/flyers/8f1c...`` です。

同じことを Swagger 上で行うときは、``GET /api/v1/flyers/{flyer_id}`` を開きます。

1. **Try it out** を押す。
2. **flyer_id** に、生成応答の ``generation_id`` だけを貼る。``/api/v1/flyers/`` は付けません。
3. **Execute** を押す。

応答は JPEG です。Swagger は画像を JSON としては出さず、ダウンロード用のリンクを出します。そのリンクから保存するか、上のアドレスを直接開いてください。

項目の意味を見る
----------------

ページ下部の **Schemas** で ``FlyerGenerationRequest`` を開くと、各項目の説明と文字数の制限が出ます。``template_id`` と ``rain_policy`` は決まった候補から選ぶ値です。候補以外の文字列を送ると 422 になります。

``rain_policy`` と ``capacity`` は省略できます。省略した雨天時の対応は「雨天決行」です。

よくある失敗
------------

* **Failed to fetch** やページが開かないときは、``uvicorn`` が止まっています。起動したターミナルを確認します。
* Code ``422`` は、JSON の項目不足や文字数オーバーです。Response body の ``message`` が利用者向けの文面です。タイトルは 2 文字以上 40 文字以内です。
* Code ``429`` は、同じ PC から 1 時間に 3 回を超えて生成したときです。``/health`` は回数に入りません。
* Code ``503`` は、言語モデルが使えなかったときです。キーを空にすればモックで生成できます。
* 画面の説明がコードと違うときは、サーバーを再起動します。``--reload`` で起動していれば、``.py`` の保存で説明も更新されます。

この画面の元は ``src/api/routes.py`` と ``src/domain/models.py`` です。ルートや項目を足すと、次の起動から Swagger に載ります。エンドポイントの意味とステータスコードは :doc:`http_api` にまとめています。
