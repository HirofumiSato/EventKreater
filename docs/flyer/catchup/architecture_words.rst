設計の言葉
==========

:doc:`/flyer/architecture` と :doc:`/flyer/pipeline` は、処理の順番よりも、部品の役割分担を先に説明します。次の語が分かれば、図を追えます。

ポートとアダプター
------------------

**ポート** は、「背景画像をください」のような依頼の形だけを決めた窓口です。中身の作り方は書きません。

**アダプター** は、その窓口の具体的な実装です。同じ「背景画像をください」に対して、OpenAI へ取りにいく実装と、ローカルでグラデーションを描く実装を差し替えられます。

この分け方の名前が Ports & Adapters（ヘキサゴナルアーキテクチャ）です。目的は、有料 API をやめて別の画像生成へ替えても、文字を置く処理を書き換えないことです。

依存の向きは、外側（OpenAI やファイル保存）が内側（依頼の形と業務の順番）を知ります。内側は外側の製品名を知りません。ガイドが「注入する」と書くのは、起動時に外側の実装を内側へ渡す、という意味です。

ユースケース
------------

**ユースケース** は、1 回の生成で行う順番です。解釈、背景取得、文字合成、一時保存、の四つを並べたクラスがそれです。HTTP の細かい形式や、OpenAI の呼び出し方はここへ書きません。

モックとフォールバック
----------------------

* **モック** は、開発とテスト用の代用品です。決まったプロンプトや、その場で描いたグラデーションを返し、外部へ通信しません。
* **フォールバック** は、本番の手段が失敗したときの予備です。画像生成が時間内に終わらないとき、テンプレート専用の静的背景で残りの処理を続けます。

モックは最初から代用品を選ぶこと、フォールバックは失敗したあとで予備へ移ること、と読み分けてください。

ガイドの図に出る部品
--------------------

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - 名前
     - 役割
   * - PromptEnginePort
     - 入力から、背景用の英語指示と色を得る
   * - ImageGeneratorPort
     - その指示から背景画像のバイト列を得る
   * - FlyerRendererPort
     - 背景と入力文字から完成 JPEG を作る
   * - StoragePort
     - 完成画像を一時的に保存し、URL を返す
   * - StaticFallbackImageGenerator
     - 画像 API 失敗時の静的背景

バイト列は、ファイルの中身そのものです。ディスクへ書く前の JPEG も、メモリ上ではバイト列です。

一時ファイル
------------

完成画像はデータベースへ永続保存しません。一定時間（TTL。既定は 1 時間）を過ぎたファイルを消します。書き込みは、いったん別名で保存してから本来の名前へ置き換えます。書きかけのファイルをダウンロードされないようにするためです。

例外
----

**例外** は、処理を続けられないことを呼び出し元へ知らせる仕組みです。ガイドでは、種類ごとに HTTP の番号が決まっています。画像生成の失敗だけは例外のまま利用者へ返さず、ユースケースが捕まえて予備の背景へ進みます。
