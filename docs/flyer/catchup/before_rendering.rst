文字合成の前に
================

:doc:`/flyer/rendering` は、完成画像を 1 枚の方眼として説明します。ピクセルと JPEG の意味は :doc:`images` にあります。ここでは、ガイドのゾーン表とコントラストの節を読むための補足だけを置きます。

ゾーンは予約席
--------------

キャンバスは幅 1080、高さ 1528 です。原点は左上で、Y は下へ増えます。ゾーン A から E は、あらかじめ場所を予約した帯です。タイトルは B、日付は C、場所や料金は D、というように、種類ごとに帯が決まっています。

テンプレートが変えるのは、揃え方・書体・文字の下地です。帯の座標そのものは 3 テンプレートで共通です。だから「バー向けだからタイトルが下に移動する」とは書かれていません。

タイトル枠
----------

ゾーン B のうち、文字に使ってよい幅は 920 px、高さは 336 px です。左右の 80 px は余白です。行は最大 3 行で、フォントサイズは 44 px から 92 px のあいだを二分探索します。長いタイトルは小さくなり、短いタイトルは大きくなります。

10 文字未満のタイトルは、そのまま最大サイズにすると周囲がスカスカになります。字間を 15 px 広げ、帯の上寄りに置いて、カテゴリ（ゾーン A）との間を詰めます。

下地と文字色
------------

文字色はテンプレートと、言語モデルが返した強調色で決まります。その色が、実際に文字の背後にあるピクセルと比べて暗すぎ・明るすぎなら、その矩形だけに黒または白の半透明の板を足します。合格の目安はコントラスト比 4.5 です。

背景が葉や照明のように細かいときは、平均の明るさだけでは読めません。エッジの強さが閾値を超えた領域はぼかし、文字に 2 px の縁を付けます。平坦な単色ではこの処理は走りません。

書体ファイル
------------

明朝・ゴシックは、プログラムが形を計算するのではなく、PC 上のフォントファイルを読みます。同梱が無いときは Windows、macOS、Linux の順で既知のファイルを探し、最初に開けたものを使います。どれも無いときだけ、文字合成は失敗します。

出力は、このキャンバスを品質 90 の JPEG にしたものです。ブラウザは受け取った画像をそのまま表示し、位置を計算し直しません。
