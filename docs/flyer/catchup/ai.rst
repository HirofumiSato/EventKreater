生成 AI の言葉
==============

:doc:`/flyer/overview` と :doc:`/flyer/pipeline` は、画像を二段階で作ります。雰囲気は AI に任せ、日付や料金の文字はプログラムが書きます。

二つのモデル
------------

* **言語モデル（LLM）** は、文章を読んで文章を返します。ここでは催しの説明を、背景用の英語の指示文に翻訳します。使っているモデル名は ``gpt-4o-mini`` です。
* **画像モデル** は、文章から絵を作ります。ここでは DALL-E 3 が背景だけを作ります。

どちらも、同じ入力でも出力が毎回少し変わります。これを確率的、と言います。反対に、同じ背景と同じ文字列なら文字の位置がずれない処理を決定論的、と言います。

プロンプト
----------

モデルへの指示文がプロンプトです。

* **システムプロンプト** は、運営側が固定する役割指示です。「文字を描くな」「余白を残せ」がここにあります。
* **ユーザーメッセージ** は、その回の依頼です。利用者が入力した店名や日時は、システムプロンプトの文中へ混ぜず、別の JSON として渡します。指示文そのものを利用者が書き換えられないようにするためです。
* **ネガティブプロンプト** は、「これの絵は描かないで」という除外リストです。文字、ロゴ、顔のアップなどが入ります。DALL-E 3 には専用の入力欄が無いので、本文の末尾に「Avoid: …」として連結します。

構造化出力
----------

言語モデルの返事を自由な文章にすると、プログラムが色コードを取りこぼします。構造化出力は、返事を決まった JSON の形に強制します。このシステムでは、英語の背景指示、除外語、強調色、遮光の濃さ、の四つです。

なぜ AI に文字を書かせないか
----------------------------

画像モデルは、日本語や数字をそれらしい形で描くことが多く、料金や日付が別の値になることがあります。告知ではその誤りが実害になります。そのため背景だけを AI に託し、文字は枠の座標へプログラムで置きます。

失敗したときの考え方
--------------------

画像モデルが時間内に絵を返せなくても、告知そのものは出せるように、テンプレートごとの静的な背景へ切り替えます。言語モデルが指示文を作れなかった場合は、何を描くか自体が決まらないので、切り替えずにエラーを返します。ガイドはこの二つを分けて書いています。
