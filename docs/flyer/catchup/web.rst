Web と HTTP
===========

ガイドの :doc:`/flyer/http_api` は、ブラウザや別のプログラムがこのシステムと会話する約束を書いています。会話の単位が HTTP です。

リクエストとレスポンス
----------------------

利用者側をクライアント、待ち受け側をサーバーと呼びます。クライアントが「これをください」「これを処理してください」と送るメッセージがリクエスト、サーバーが返すメッセージがレスポンスです。

このシステムのサーバーは、自分の PC 上で起動するプログラムです。案内に出てくる ``http://127.0.0.1:8000`` は「この PC 自身の 8000 番窓口」です。インターネットに公開しなくても、同じ PC のブラウザから届きます。

URL は住所です。``/health`` や ``/api/v1/flyers/generate`` は、そのサーバーの中のどの機能かを指します。``{flyer_id}`` のように波括弧で書いた部分は、実際のリクエストでは具体的な値に置き換わります。

メソッド
--------

URL だけでなく、「何をしたいか」も一緒に送ります。ガイドに出るのは次の二つです。

* **GET** は、すでにあるものを取りにいきます。死活確認と、完成画像のダウンロードです。
* **POST** は、新しい処理を頼むときに使います。チラシ生成は、入力データを添えた POST です。

JSON
----

生成の依頼と、その返答は JSON というテキストです。``{ }`` の中に ``"名前": 値`` をカンマで並べます。文字列は二重引用符で囲みます。ガイドのリクエスト例は、そのまま POST の本文になります。

ステータスコード
----------------

レスポンスの先頭には、成否を表す 3 桁の番号が付きます。ガイドの表は、この番号で分岐しています。

.. list-table::
   :header-rows: 1
   :widths: 12 88

   * - 番号
     - このガイドでの読み方
   * - 200
     - 処理できた。画像生成が失敗しても、代わりの背景で絵が完成していれば 200 です。
   * - 404
     - その住所のファイルは無い。期限切れの画像 ID もここに含みます。
   * - 422
     - 届いた JSON の形や文字数がルールに合わない。
   * - 429
     - 同じ相手から短時間に頼みすぎたので断った。
   * - 500
     - サーバー内部で描画などに失敗した。
   * - 503
     - 言語モデル側が使えず、処理を開始できなかった。

番号と一緒に、``error_code`` という機械向けの名前と、人向けの日本語メッセージが JSON で返ります。

補足の言葉
----------

* **IP アドレス** は、通信相手のネットワーク上の番号です。レート制限は、この番号ごとに回数を数えます。
* **Swagger UI** は、起動中のサーバーが ``/docs`` に出す試験用の画面です。ボタンの押し方は :doc:`/flyer/swagger` にあります。
* **UUID** は、衝突しにくいランダムな識別子です。完成画像のファイル名に使います。
