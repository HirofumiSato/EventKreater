生成パイプラインの前に
========================

:doc:`/flyer/pipeline` の「パイプライン」は、分岐メニューではなく、毎回同じ四段の直列です。前の段の出力が、次の段の入力になります。

.. code-block:: text

   入力 JSON
     → 英語の指示と色（コンテキスト）
     → 背景のバイト列
     → 文字を焼いた JPEG
     → 一時 URL

段と段のあいだで受け渡すものは、画面ではなくデータです。画像はまだファイル名ではなく、メモリ上のバイト列です。最後の段で UUID のファイル名になり、``/api/v1/flyers/{id}`` として返ります。

二つの失敗は扱いが違う
----------------------

背景を描く段だけが、失敗しても先へ進みます。

* 画像生成は 25 秒の予算を持っています。その内側で最大 2 回試します。予算を使い切ったら、テンプレート用の静的背景に差し替えて文字合成へ進みます。HTTP は 200 のままで、``status`` が ``fallback_used`` になります。
* 言語モデルが指示文を作れなかったときは差し替えません。何を描く背景かが決まらないためです。このときは 503 です。

「例外を捕捉する」は、エラーで処理を止めず、その場で予備手段へ移る、という意味です。画像の失敗だけ捕捉し、言語モデルの失敗は捕捉しません。

指示文の渡し方
--------------

言語モデルへの固定ルール（文字を描くな、余白を残せ）はシステムプロンプトです。利用者の店名や日時は、その文面へ連結せず、別のユーザーメッセージとして JSON で渡します。詳しくは :doc:`ai` にあります。

画像モデルへ渡す縦横比は ``9:16`` です。DALL-E 3 には「描くな」専用の欄が無いので、除外語は英語指示の末尾にくっつけます。

この順を頭に置いてから、ガイドの番号付きリストを読んでください。
