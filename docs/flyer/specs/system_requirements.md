# システム要件定義書

## プロジェクト: 小規模店舗・イベント主催者向け AIチラシ自動生成Webアプリ

## 1. システム概要とアーキテクチャ境界

### 1.1. システムの目的

本システムは、個人経営店舗（バー、サロン、カフェ等）や、飯フェス、タコパ、ライブ、占い、撮影会などを開く小規模イベント主催者が、デザインの専門知識や工数をかけることなく、事実情報の入力のみで告知ページと A4 配布に適した高品質チラシ画像（A4 縦）を即座に取得できるWebアプリケーションである。

### 1.2. 階層的ポジショニング

```
【最上位：企画要件】
  └ 目的：店舗オーナーの告知作成摩擦をゼロにし、45秒以内に集客用画像を届ける
      ↓
【本ドキュメント：システム要件定義】
  ├ 機能要件（FR）：何をシステムが自動化し、何を決定論的に描画するか
  ├ 非機能要件（NFR）：コスト上限、レイテンシ、フォールバック、可搬性（Mac mini移行）
  └ システム境界：決定論的描画層と確率的AI層の責任分解
      ↓
【次工程：実装仕様書】
  └ APIエンドポイントスキーマ、JSON Schema、レンダリング座標テーブル、プロンプトテンプレート
```

### 1.3. ハイブリッド描画アーキテクチャ

AIの確率的出力による「文字化け」「誤字」「数字改変」を根本排除するため、システム境界を以下の2層に厳密に分離する。

```
+-------------------------------------------------------------------------+
| [クライアント (Web/Mobile Browser)]                                    |
|   - 入力フォーム（イベント名、日時、場所、費用、雨天対応、上限人数）      |
|   - テンプレート選択（3種） / プレビュー表示 / ダウンロード             |
+------------------------------------+------------------------------------+
                                     | JSON (REST API)
                                     v
+-------------------------------------------------------------------------+
| [バックエンド (FastAPI / Node.js)]                                      |
|                                                                         |
|  +-------------------------+      +----------------------------------+  |
|  | 【確率的AI層】          |      | 【決定論的レンダリング層】       |  |
|  |  1. プロンプト生成 (LLM)|      |  3. テキスト・レイアウト合成     |  |
|  |     (gpt-4o-mini等)     |      |     (Pillow / Skia / Satori)     |  |
|  |           ↓             |      |     - 指定座標への文字描画       |  |
|  |  2. 背景画像生成 (API)  | ---> |     - 背景明暗に応じた遮光マスク |  |
|  |     (SDXL / Flux / etc) |      |     - 商用フリー日本語フォント   |  |
|  +-------------------------+      +-----------------+----------------+  |
+-----------------------------------------------------|-------------------+
                                                      v
                                        [完成画像 (PNG/JPEG)]
```

## 2. システム構成とポータビリティ設計

### 2.1. インフラストラクチャ構成

* **フロントエンド:** SPA / SSR (React, Next.js, or Vue.js)
* **バックエンド:** 軽量APIサーバー (Python FastAPI 推奨: 画像処理ライブラリ Pillow との親和性およびAI SDK親和性のため)
* **ストレージ:** 一時画像キャッシュ (ローカルメモリ / 一時ファイルストレージ、TTL 1時間で自動揮発)

### 2.2. AIサービス・プロバイダ抽象化レイヤー (Adapter Pattern)

将来的な「Mac mini (Ollama / Local Stable Diffusion)」への完全移行をコード改修なしで実現するため、バックエンド内にアダプター層を設ける。

```
[生成パイプラインコア]
       │
       ├──> [LLM Adapter] ───────┬─> (Cloud) OpenAI gpt-4o-mini
       │                         └─> (Local) Ollama / Llama-3-8B (Mac mini)
       │
       └──> [ImageGen Adapter] ──┬─> (Cloud) Replicate / DALL-E 3
                                 └─> (Local) SD.Next / ComfyUI API (Mac mini)
```

## 3. 機能要件 (Functional Requirements)

### FR-01: イベント情報入力機能

ユーザーがチラシ生成に必要な事実情報を入力するフォームを提供する。

* **入力フィールド仕様:**
  1. **催し名（タイトル）:** 必須、全角30文字以内。
  2. **開催日:** 必須、日付ピッカーまたはテキスト形式（例: `2026-11-15`）。
  3. **開催時間:** 必須、全角20文字以内（例: `19:00〜22:00 (Open 18:30)`）。
  4. **費用（料金）:** 必須、全角25文字以内（例: `¥3,000 (1ドリンク付)`）。
  5. **開催場所:** 必須、全角35文字以内（例: `Jazz Bar MOON (新宿駅東口徒歩5分)`）。
  6. **雨天時対応:** 任意、選択式または全角15文字以内（例: `雨天決行` / `荒天中止` / `屋内開催`）。
  7. **定員・上限人数:** 任意、全角15文字以内（例: `先着20名様限定`）。

* **バリデーション:**
  * 必須項目の未入力チェック。
  * 最大文字数超過時のリアルタイム警告（レンダリング時の文字溢れ防止）。
  * 特殊制御文字、HTMLタグ、スクリプト文字のエスケープ処理。

### FR-02: テンプレート（世界観）選択機能

ユーザーはあらかじめ用意された3つのデザインプリセットから1つを選択する。

* **プリセット定義:**
  1. **Pattern A: 「シンプル・スタイリッシュ」**
     * 対象: バー、ナイトイベント、ジャズライブ、個展、占い。
     * ビジュアルトーン: ダーク、コントラスト高め、モノトーン＋差し色、洗練、静寂。
     * タイポグラフィ: 明朝体・セリフ体基調、文字間広め。
  2. **Pattern B: 「温かみ・アットホーム」**
     * 対象: ワークショップ、個人サロン、料理教室、アコースティックライブ、タコパ、撮影会。
     * ビジュアルトーン: アースカラー、木目、やわらかな自然光、水彩・テクスチャ感。
     * タイポグラフィ: 丸ゴシック・やわらかい明朝基調。
  3. **Pattern C: 「イベント・フェス」**
     * 対象: マルシェ、屋外マーケット、ポップアップ、周年パーティ、飯フェス。
     * ビジュアルトーン: ビビッド、祝祭感、賑やか、ダイナミックな構図。
     * タイポグラフィ: 太字サンセリフ（ゴシック体）基調、情報強調型。

### FR-03: プロンプト生成エンジン (LLM層)

入力情報とテンプレートIDをバックエンドが受け取り、画像生成用の英語プロンプトを構築する。

* **処理フロー:**
  1. システムプロンプトにより、LLM（`gpt-4o-mini`）へ催し名、場所、選択テンプレートを渡す。
  2. LLMは催しの「雰囲気」「連想されるキービジュアル」を抽出し、**テキストや文字を一切含まない英語の背景プロンプト**を生成する。
  3. システム側で固定のスタイルアンカー（画質指定、画風固定）およびネガティブプロンプトを連結する。
* **ネガティブプロンプト強制付与:**
  * `text, letters, words, typography, logo, watermark, signature, blurry, low quality, distorted human faces` を常時結合し、AIに文字を描かせない。

### FR-04: 背景画像生成エンジン (ImageGen層)

生成されたプロンプトを画像生成APIに送信し、アスペクト比に適合した背景画像を取得する。

* **アスペクト比:**
  * 初期MVP: `A4`（1080×1528px）に固定する。画像生成APIに A4 相当のサイズは無いため、縦長（9:16）で取得し、レンダラーが A4 縦へ cover で切り抜く。
* **出力形式:** PNGまたは高画質JPEG（RGB）。

### FR-05: テキスト・画像合成レンダリングエンジン (決定論的描画層)

生成された背景画像の上に、ユーザー入力テキストをプログラムで正確にオーバーレイ描画する。

* **描画規則:**
  * **文字可読性保証（Scrim処理）:** 背景画像の明度に関わらず文字を視認可能にするため、テキスト配置エリアの背景に半透明グラデーション（黒または白のアルファマスク）またはテキストシャドウ（ドロップシャドウ/縁取り）を強制合成する。
  * **フォントバインド:** 商用利用フリーのオープンソースフォント（Google Fonts: Noto Sans JP、Noto Serif JP、M PLUS Rounded 1c等）をサーバーに内包し使用する。
  * **レイアウト自動縮小:** 入力文字列が想定幅を超えた場合、フォントサイズを自動で段階的に縮小（オートスケーリング）して枠内に収める。

### FR-06: プレビュー及びダウンロード機能

* **プレビュー表示:** レンダリング完了後、Web画面上に生成画像を即座に表示（ローディング中はプログレスアニメーションを表示）。
* **画像ダウンロード:** ユーザーのブラウザへワンクリックでPNG/JPEGファイルを直接保存させる。
* **再生成（リトライ）機能:** 同一の入力内容のまま、背景画像のみを再生成する「別の背景で試す」ボタンを提供する（回数制限あり）。

### FR-07: 利用制限・アクセス制御機能

* **レートリミット:** 1IPアドレスまたはブラウザCookie単位で、1時間あたり最大3回、月間最大5回までの生成制限を実施（API破産防止）。
* **コストキルスイッチ:** システム全体の日次API利用金額が一定値（例: 1日$10）を超過した場合、新規生成を自動停止し、メンテナンス表示へ切り替える。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1. 性能・レイテンシ要件 (Performance)

* **NFR-P01: 応答速度 (Time-to-Asset):**
  * 入力完了から完成画像プレビュー表示までの総待機時間: **45秒以内（中央値30秒以内）**。
  * 内訳目標:
    * LLMプロンプト生成: 2秒以内
    * 背景画像生成API: 15〜25秒以内
    * 合成レンダリング処理: 1秒以内
* **NFR-P02: 同時リクエスト制御:**
  * 初期MVPでは同時実行数を最大3リクエストに制限。超過分はキューイング（待機列）または「混雑中」のエラー応答を返す。

### 4.2. コスト・インフラ制約 (Cost & Budget)

* **NFR-C01: 1生成あたりのAPI原価:**
  * **10円未満 / 回**（1ウィザード = AI背景 最大3枚 ＋ LLM 4回）を達成すること。`gpt-image-2.5-flare` / `low` / `1024x1536`（1枚 約 $0.005）と `gpt-4o-mini` の組み合わせで、1 USD = 200 円として約 3.3 円。価格表は `src/domain/pricing.py` が持ち、`tests/test_cost_budget.py` が上限を固定する。損益分岐は約 667 円/USD。`gpt-image-2.5` 系は画像出力 $30 / 1M トークンの課金で、1 枚あたりの定価は公表されていないため、代表サイズの換算値を切り上げて表に持つ。
* **NFR-C02: ストレージ費用ゼロ運用:**
  * 生成画像は永続データベースに保存せず、生成後1時間経過した一時ファイルはcronバッチで物理削除する（ストレージ課金の極小化）。

### 4.3. 信頼性・フォールバック設計 (Reliability & Resilience)

* **NFR-R01: 外部API障害時のフォールバック:**
  * 画像生成APIがタイムアウト（30秒超過）またはエラーを返した場合、各テンプレートに事前用意された「静的デフォルト背景画像（テクスチャ画像等）」を自動適用してレンダリングを完遂させ、ユーザーに空手（生成失敗）で返さない。
* **NFR-R02: 例外ハンドリング:**
  * エラー発生時、ユーザーには技術的なエラーコードではなく「ただいま生成が混み合っています。少し時間をおいてお試しください」といった平易な日本語メッセージを表示する。

### 4.4. 移植性・拡張性 (Portability & Modularity)

* **NFR-M01: Mac miniローカル移行容易性:**
  * AI呼び出しインターフェース（`generate_prompt()`, `generate_background()`）を抽象基底クラスとして実装し、環境変数の切り替えのみでクラウドAPIからローカルMac mini（Ollama + ComfyUI API）へ差し替え可能とすること。

### 4.5. セキュリティ・法的適合性 (Security & Legal)

* **NFR-S01: プロンプトインジェクション対策:**
  * ユーザー入力文字列がLLMのシステムプロンプトを上書きしないよう、入力は必ずJSON構造内の変数（User Message）として隔離して渡す。
* **NFR-S02: コンテンツモデレーション:**
  * 公序良俗に反する単語、反社会的な語句、暴力・成人向けコンテンツを排除するため、LLM前処理またはOpenAI Moderation APIによるフィルタリングを行う。
* **NFR-S03: ライセンス担保:**
  * 使用するフォント（SIL Open Font License準拠）、合成ライブラリ、および生成モデルの商用利用ライセンスが抵触しないことを担保する。

### 4.6. ユーザビリティ (Usability)

* **NFR-U01: モバイルファーストUI:**
  * 店舗オーナーが仕込み中や休憩中に片手で操作できるよう、スマートフォン画面（幅375px以上）で完全に操作が完結するレスポンシブデザインとする。

## 6. 自己反証とトレードオフ分析

本システム要件を策定するにあたり検討された3つのトレードオフと対策である。

### 反証1: サーバー側レンダリング（SSR画像合成） vs クライアント側（HTML Canvas）レンダリング

* **批判:** クライアント（ブラウザのCanvas）で文字を合成すれば、サーバーのCPU負荷・メモリ消費はゼロになり、コストを最小化できるのではないか？
* **判定 (サーバー側採用):** モバイル端末ごとのフォントレンダリングエンジン差異、フォント読み込み失敗時の文字化け、および端末スペックによる合成破綻を防ぐため、サーバー側（Pillow/Node-Canvas）で決定論的に1枚のビットマップ画像として焼き込んで返す構成を採用する。信頼性を最優先とする。

### 反証2: 事前生成背景ライブラリ vs 都度AI生成

* **批判:** 毎回AIに背景を生成させず、デザイナーが作った背景画像を100枚用意してランダム選択させた方が、コスト0円かつレイテンシ0秒で済むのではないか？
* **判定 (ハイブリッド都度生成採用):** 「ジャズライブ」「クラフトビール試飲会」「タロット占い」といったイベント特有の微細な世界観の一致こそがユーザーの感動（「自分の店のイベントに合っている」）を生む。ただし、障害時のフォールバックとして事前生成背景を常備することで、両者の利点を統合する。

### 反証3: 画像アスペクト比の固定 vs 自由選択

* **批判:** A4印刷用やTwitter横長（16:9）など、多様なサイズに対応すべきではないか？
* **判定 (A4 縦 1 サイズ採用):** MVPフェーズでは、主催者が配る紙のチラシと告知ページの QR を 1 枚にまとめられる「A4 縦（1080×1528）」に固定する。レイアウト破綻の変数を最小化し、開発工数をコア機能に集中させる。横長・正方形は需要を見てから足す。
