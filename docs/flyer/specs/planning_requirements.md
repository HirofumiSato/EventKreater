# プロジェクト企画要件定義書
## 小規模店舗・イベント主催者向け AIチラシ自動生成Webアプリ

## 1. 目的と位置づけ（階層構造）

本ドキュメントは、システム要件定義および実装仕様の策定に先立ち、プロダクトの「目的関数（Evaluation Function）」を定義するものである。上位の企画要件を固定化することで、後続フェーズにおける機能の取捨選択と非機能要件の境界設定を可能にする。

```text
【最上位：企画要件（本ドキュメント）】
  └ 誰のどんな痛みを、既存代替品と比べてどう解決し、どう事業成立させるか
      ↓
【次工程：要件定義書（システム境界・機能/非機能）】
  └ その価値を提供するために、システムが何を担保し、何を切り捨てるか
      ↓
【最終工程：仕様書（APIスキーマ・合成座標・プロンプト構文）】
  └ 具体的な実装パラメータ、データ構造、レンダリング定義
```

## 2. 企画要件コア5項目

### 2.1. ターゲットの解像度と現状の代替手段

#### プライマリペルソナ
* **属性:** 個人経営バーの店主、小規模サロンオーナー、ワークショップ主催者（1〜2名で店舗・事業を運営）。
* **技術・リテラシー:** スマートフォンの操作は日常的だが、デザインツール（Illustrator、Canva等）のレイヤー概念やタイポグラフィ選定に苦手意識がある。
* **行動コンテキスト:** 仕込み、接客、在庫管理に追われ、告知画像作成にかけられる時間は「営業開始前の10分間」または「休憩中のスマートフォン操作」に限られる。

#### 現状の代替手段（As-Is）と課題
* **Canva / Adobe Express:**
  * テンプレート数が多すぎて選定に迷う。
  * テキストの打ち替えや配置調整に30分以上消費する（「自由度の高さ」が認知的摩擦となる）。
* **SNS（LINE・Instagram等）のテキスト直打ち告知:**
  * 単色背景のストーリーや文字投稿で済ませるが、タイムライン上で視覚的に埋没し、集客効果が低い。
* **クラウドソーシング外注（ココナラ等）:**
  * 1枚あたり3,000円〜10,000円程度のコストと数日間のやり取りが発生するため、小規模な突発イベント（例: 「今週金曜の即興ライブ」等）には費用・納期面で適合しない。

---

### 2.2. 独自の提供価値（Core Value Proposition）

#### デザイン作業の完全消滅（Zero-Design Effort）
* ユーザーにデザインの試行錯誤を一切要求しない。
* イベント名、日時、場所、費用等の確定した事実情報を入力し、あらかじめ用意された3つのデザイン世界観から1つを選択するだけで、**30秒以内に可読性が保証されたポスター画像**が出力される。

#### 「文字崩れゼロ」と「世界観生成」のハイブリッドアーキテクチャ
* 画像生成AI特有の日本語文字化けや数字の改変リスクを排除するため、テキスト情報はプログラム制御（Pillow/Canvas等）による固定レンダリング層で描画する。
* イベントの雰囲気に合わせた背景ビジュアルのみをLLMおよび画像生成APIで動的に生成することで、正確な情報伝達と視覚的魅力を両立する。

### 2.3. 成功指標（KPI / ガードレール指標）

| 指標区分 | 指標名 | 目標値 | 計測定義 / 意図 |
| :--- | :--- | :--- | :--- |
| **UX摩擦** | Time-to-Asset (TTA) | 45秒以内 | 入力画面表示から画像ダウンロード完了までの所要時間中央値 |
| **受容性** | 初回ダウンロード完了率 | 70%以上 | 生成完了画面に到達したセッションのうち、保存アクションが実行された割合 |
| **品質** | 1発採用率 (One-Shot Ratio) | 60%以上 | 背景画像の再生成（リトライ）を行わずに保存された割合 |
| **信頼性** | 文字視認性欠陥率 | 0.5%未満 | 背景明度と文字色のコントラスト不足、改行崩れ等のレイアウト不具合発生率 |

### 2.4. ユニットエコノミクス・採算仮説

#### 1生成あたりの売上原価（COGS）推計
* **テキスト解釈・プロンプト生成 (`gpt-4o-mini`):**
  * 入力約200トークン＋出力約300トークン $\approx$ 約0.02円
* **背景画像生成API:**
  * *パターンA（OpenAI DALL-E 3 Standard）:* 約6.0円〜8.0円 / 枚
  * *パターンB（Replicate経由 SDXL / Flux Schnell等）:* 約0.5円〜1.5円 / 枚
* **合計インフラ原価:** 1生成あたり **約0.6円〜8.0円**

#### マネタイズ展開のフェーズ設計
* **フェーズ1（検証期）:**
  * 完全無料公開。
  * IP/Cookie制御による1ユーザーあたり月3回までの生成上限を適用。
* **フェーズ2（収益化期）:**
  * **Freeプラン:** 月2回まで生成可能（微小なサービスロゴを付与）。
  * **Proプラン（月額480円 または 都度100円/回）:** 生成無制限、高解像度出力、店舗ロゴ追加機能。
  * ※月5回生成時のインフラ原価は約5円〜40円であり、月額480円の価格設定で粗利益率90%以上を確保可能。

### 2.5. やらないことリスト（Non-Goals）

開発スコープの肥大化とデザイン品質の破綻を抑止するため、初期バージョン（MVP）において以下を明確に対象外とする。

1. **WYSIWYG（自由配置・ドラッグ＆ドロップ）エディタの実装:**
   * 文字の座標移動、サイズ変更、自由なテキストボックス追加は許可しない。レイアウト破綻を防止し、入力即生成の体験を最優先とする。
2. **自由なフォント選択・カラーパレット指定:**
   * フォントはテンプレートごとに可読性を検証済みの商用フリーフォント（Noto Sans JP、M PLUS 1p、しっぽり明朝等）をシステム側で固定バインドする。
3. **印刷入稿用データ（CMYK / 350dpi / トンボ付きPDF）の生成:**
   * SNS告知（Instagramストーリー 9:16、正方形 1:1）を主眼としたRGBデジタル画像（PNG/JPEG）の出力に限定する。
4. **プロンプト直接入力・編集機能:**
   * ユーザーに画像生成プロンプトを直接触らせない。プロンプトエンジニアリングはすべてバックエンドのLLM側で隠蔽する。

## 3. 想定される3つの自己反証と構造的批判

本企画を実装・運用するにあたり想定されるリスク要因と批判的視座である。

### 批判1: カスタマイズ欲求の爆発（Customization Paradox）
* **内容:** 個人店舗の店主はこだわりが強く、「ロゴを入れたい」「色を変えたい」という微調整要求が必ず生じる。自由度を排除した設計は、初期の簡易さで惹きつけつつも、実際の告知直前で「融通が利かない」として離脱されるリスクがある。
* **対抗仮説:** 初期ターゲットを「こだわりが強い層」ではなく、「告知作成に1分もかけられない疲弊層」に絞り込み、極小の手間で及第点を出す価値を優先する。

### 批判2: 背景画像の文脈不一致（Semantic Disconnect）
* **内容:** LLMが自動生成したプロンプトで背景画像を作成する場合、「アコースティックライブ」に対してサイバーパンク調の画像が出力されるなど、店舗の空気感と乖離した生成物が返る確率をゼロにできない。
* **対抗仮説:** テンプレート選択時に「ネガティブプロンプト」や「画風スタイルアンカー」を固定付与し、生成領域のブレ幅を厳格に制限する。

### 批判3: 外部API依存による原価急変の脆弱性
* **内容:** 画像生成APIの価格改定や規約変更により、ユニットエコノミクスが外部要因で破綻するリスクを内包する。
* **対抗仮説:** LLMおよび画像生成プロバイダを抽象化レイヤー（Adapterパターン）で分離し、Replicate、OpenAI、またはローカルMac mini環境へコード変更なしで差し替え可能な設計とする。

## 4. 難易度順の参照フレームワーク

本企画要件をより堅牢なプロダクト設計へと深化させるための3段階の参照ソースである。

* **Step 1（基礎原理）: Anthony Ulwick『Jobs to be Done: Theory to Practice』**
  * *視座:* 「チラシを作ること」ではなく「集客の心理的負担をゼロにすること」というジョブの解像度を高め、不要な付加機能の削ぎ落としを徹底する。
* **Step 2（実装・実践）: Gabriel Weinberg, Justin Mares『Traction: A Startup Guide to Getting Customers』**
  * *視座:* ツール単体の完成度にとどまらず、小規模店舗オーナーへの認知獲得経路（飲食店組合、地域コミュニティ等）と機能要件を連動させて設計する。
* **Step 3（最先端の限界）: Chip Huyen『Designing Machine Learning Systems』**
  * *視座:* 確率的出力（非決定性）を抱えるAIシステムにおいて、生成エラー時のフォールバック設計やガードレール指標を運用レベルで定義する。
