イベント作成の音声入力
============================

イベント作成画面（ ``/organizer/events/new`` ）の右下にマイクボタンを固定し、押すと音声モードに入ります。
音声モードに入るとそのまま録音が始まり、1 欄ずつ話して埋めていきます。
直前に選んでいた入力欄があればその欄から、無ければ上から順に空欄へ「見た目だけのフォーカス」を当てます。

このページは、音声入力の使い方と、OpenAI の音声認識 API の導入手順をまとめます。
実装の正はコードです。差分を見つけたら、コードとこのページを同じ PR で直します。

仕組み
------

音声はブラウザで録音し、アプリの API を通して OpenAI の音声認識へ中継します。
返ってきた文字を、欄ごとの決まった規則でフォームの値に変換します。
認識は 1 回の問い合わせの中で途中経過（ ``delta`` ）を返すため、画面は話し終わる前から文字を受け取れます。

.. code-block:: text

   マイク
     → MediaRecorder（webm/opus。Safari は mp4）
     → POST /api/v1/voice/transcriptions（アプリのサーバー）
     → POST https://api.openai.com/v1/audio/transcriptions（OpenAI, stream=true）
     → text/event-stream（delta を順に中継し、done で全文）
     → src/modules/events/lib/voice/parse.ts（欄ごとの抽出）
     → EventFormValues の部分更新

まとめて話すときは、経路が 1 本増えます。文字起こしは 1 回だけで、その全文を
決まった手順で節に分け、欄へ割り当てます。

.. code-block:: text

   マイク
     → POST /api/v1/voice/utterances（アプリのサーバー）
     → 文字起こし 1 回（gpt-transcribe）
     → src/modules/events/lib/voice/utterance.ts（決定的な割当）
     → 未割当の節だけ LLM に「どの欄の話か」を聞く（値は作らせない）
     → parse.ts を通したパッチ

文字を値に変える部分は LLM を使いません。欄が決まっていれば、日付・時刻・金額・人数は
正規表現と辞書で決定的に読めます。同じ発話が常に同じ値になるため、テストで仕様を固定できます。
まとめて話すときの LLM も、返すのは「どの節がどの欄か」だけで、値は必ず ``parse.ts`` に通します。

値は文脈で読む
^^^^^^^^^^^^^^

``parse.ts`` と ``normalize.ts`` は、いまの日付（ ``now`` ）、フォームの現在値（ ``value`` ）、
対象の行（ ``row`` ）を受け取ります。そのため、次の言い方をそのまま受けます。

* 月を言わない「5日」、「来月」「再来月」「今月末」「来月末」、曜日（「次の土曜」「来週の金曜」）
* 「朝から」「昼から」「夜7時」、「18時から2時間」（終了時刻を計算）、「2時間半」
* 都道府県の略称（「東京」→「東京都」）
* 期限の相対表現（「前日」「当日」「3日前」「1週間前」）
* 金額・定員の「1人3000円」「3000円くらい」「30人くらい」

0 時をまたぐ長さ（「23時から2時間」など）は、翌日へ回さずに値を入れません。読み直してください。

画面の操作
----------

.. list-table::
   :header-rows: 1
   :widths: 26 74

   * - 操作
     - 動き
   * - 右下のマイクボタン
     - 音声モードに入り、そのまま録音を始める。もう一度押すと終了する。 ``Esc`` でも終了する。地はリンクで見慣れた青（ ``--color-link-blue`` #0b57d0）で、マイクはその青を白で薄めた淡い青。縁と影は置かない。録音中だけ朱（ ``--color-primary``）に変えて、押せる状態と録っている状態を色で分ける
   * - 初回の案内
     - マイクボタンだけを丸く切り抜いた黒透過の案内を出す。見出し「ラクちん音声入力」と本文「話し方を選ぶと、録音が始まります。」、話し方の 2 択（「まとめて話す」「1つずつ」）を 1 列に積み、「次回から表示しない」を示す。見出しは「何の機能か」だけでなく「手軽さ」まで言い、下だけ山吹の太い線（3px）で引いて目を引く。文字の背後を塗る蛍光ペンにしないのは、地が吹き出しと近い色で、背後の帯が文字の輪郭を濁すため。2 択は同じ装飾で並べ、片方を推す札は置かない。どちらも白い紙に墨の縁（1px）を付け、右下へ山吹の硬い影（3px）を落としたボタンにし、右端に押せる印の山形を置く。縁を 1px にするのは、吹き出し自身の縁（2px）と太さを並べないため。中身は左そろえの 2 行で、1 行目が話し方の名前（15px・太字）、2 行目がどの催しに向くかの札（まとめてが「シンプルなイベント向け」、1つずつが「複数日程・費用男女別向け」）。札は山吹を 22% に薄めた地で塗り、補助文字の 11px で置く。塗らないと補足文に沈んで手掛かりにならず、濃く塗るとボタンの影と同じ色が内側にもう 1 つ入ってごちゃつくため。札の長さが違っても 2 枚が同じ形に見えるよう、右端に寄せず名前の下へ積む。2 択を押すと閉じて、その話し方のまま録音を始める。黒い面・吹き出し・ ``Esc`` で閉じる。マイクボタンを押すと閉じて、空欄の数と行の形から決めた話し方で入る
   * - 音声モードに入る前に入力欄を選んでいる
     - その欄から始める。選んでいなければ、上から見て最初の空欄から始める
   * - パネルの見出し
     - 1 欄ずつのときは質問と例（「催しの名前は？ 例: 忘年会」）を 1 行に並べる。入力済みの欄では、その下に「いまの値: …」を小さく出す。まとめてのときは、1 つの欄の話ではないので質問を進めず、「以下をまとめて話してください」を固定で出す。進み具合はマスの塗りだけで示す。その下に、話す順の欄の名前を並べたマス（イベント名・開催日・開始時間と終了時間・費用プラン名・費用（～円）・場所・郵便番号の 7 枚まで）を置く
   * - まとめて話す 1 文の例
     - マスの下（主ボタンのすぐ上）に、「以下をまとめて話してください」と「例 忘年会、12月5日、18時から20時、一般、3000円、渋谷ホール、1500001」を置く。マスの名前だけでは、値として何を言えばよいか分からないため。例は話す順に値を並べた 1 文で、開始と終了は「18時から20時」の 1 つに畳む。枠も地も足さず、字だけで置く。1 つずつのときは出さない
   * - 任意の項目も聞く
     - 空欄でよい欄（費用の補足・雨天時の方針・定員・申し込み期限）まで聞くかの切り替え。まとめてでは既定で外し、1つずつでは既定で入れる。開いているあいだは付け外しでき、話し方を切り替えるとその話し方の既定に戻る。外すと、話す順のマスも 1 文の例も必須の欄だけになる
   * - 話し方（2 択）
     - 「まとめて」「1つずつ」のラジオ。必須の空欄が 3 つ以上で、日程・費用の行が 1 つのときは「まとめて」を既定にする。複数日程・費用男女別・複数の費用プランがあるときは「1つずつ」を既定にする。必須の空欄だけで数えるのは、まとめてが任意の欄を外すため（任意を数えると、話す欄が 2 つしかないのに 1 回で聞くことになる）。切り替えても録音はそのままで、停止したあとの送り先だけが変わる
   * - 録音中（REC の印）
     - 質問文は消さず、REC の点と「録音中」で状態を示す。停止ボタンは赤い四角に変わる
   * - 録音中に出る吹き出し
     - 主ボタンの真下に「話し終わったら」「タップ」の 2 行を、灰色（ ``--color-text-subtle`` ）の小さな文字だけで出す。スキップの下にも同じ大きさ・色で「スキップ」を出す。枠・塗り・尾（吹き出しの三角）は付けない
   * - 停止ボタン（赤い四角）
     - 録音を止めてテキストへ変換する。変換中は質問の代わりに「テキスト変換中」を小さく出す。以降は「答えたら次へ」の設定に従う
   * - 途中経過（聞き取りの表示）
     - 録音を止めてから文字が届くまでのあいだ、聞き取れた文字を質問の下に 1 行ずつ伸ばす。質問は消さず、話しながら確かめられる。増分を足していくので、応答をためるプロキシを通ると最後にまとめて出る
   * - 録音を止めたあとの確認
     - 自動確定しない欄（催しの名前・会場名・市区町村・町域・番地・建物名・プラン名・補足など）は、題を「入力内容の確認」に固定したダイアログで確かめる。本文には欄の名前と入力欄を置き、聞き取った文字を初期値にする。直してから「確定」でフォームへ入れ、「再録音」で同じ欄を録り直す。話したままの文字は本文の下に「話した内容: 「…」」として残す。閉じても値は入れず、同じ欄に留まる
   * - 自動確定する欄
     - 開催日・開始・終了・金額・定員・郵便番号・都道府県・雨天時の方針・申し込み期限は、読めた時点で確認を挟まずに入れる。パネルに「開催日を「12月5日」で入力しました」を 3 秒だけ出す
   * - 読めなかったとき
     - 自動確定する欄でも、読めなければ確認を出す。聞き取った生の文字を入力欄の初期値にし、直してから確定できる
   * - まとめて話す
     - 話し方を「まとめて」にすると、30px の行は「以下をまとめて話してください」の固定の指示になる。1 つの欄の話ではないので質問は進めず、進み具合はマスの塗りだけで示す。その下に、話す順の欄の名前を並べたマス（イベント名・開催日・開始時間と終了時間・費用プラン名・費用（～円）・場所・郵便番号）を 7 枚まで置く。マスは空欄の欄から作り、同じ行の開始と終了は「開始時間と終了時間」の 1 枚に畳む。名前は `fields.ts` の欄の名前を使い、金額のように単位を添えないと何を話すか決まらないものだけ「費用（～円）」と短くする。任意の欄（補足・雨天時・定員・期限）は既定で外す。マスの下、主ボタンのすぐ上に 1 文の例（「例 忘年会、12月5日、18時から20時、一般、3000円、渋谷ホール、1500001」）を置く。録音中は、聞き取れて言い終わった節のマスから順に点と縁が変わる（値は入れない）。録音は 1 回だけで、止めると「まとめて入力します」のダイアログに欄ごとの行（取り込むチェック・欄の名前・入力）を並べる。先頭に「Nつの欄に入れます。」、空欄なのに割当が付かなかった欄があれば「入らなかった欄: …」を出す。チェックを外した行は反映しない。当たらなかったことは「入らなかった欄: …」の 1 行に欄の名前だけでまとめ、話した言葉は並べない（同じ失敗を言葉と名前の 2 行で言わない）。「すべて入力」でチェックの入った行だけを 1 回の更新にまとめて反映する
   * - 一括を取り込んだあと
     - 反映したあと、必須の空欄が 2 つ以上残っていれば「まとめて」のまま閉じ、「あとNつ。続けて話せます。」を出す。録音は自動で始めない（話す準備ができてからマイクを押す）。1 つ以下なら「1つずつ」に切り替え、「残りの欄は1つずつ話します。」を出して、最初の未入力欄の録音を始める
   * - 開催日時を埋めたあとの質問
     - その行の開催日・開始・終了がそろうと「別の日程も追加しますか？」と聞く。「はい」で行を足し、その行の開催日へ進む
   * - 費用を聞く前の質問
     - 費用の最初（プラン名）を聞く直前に、1 セッション 1 回だけ「男女別の費用を設定しますか」と聞く。「男女別にする」で男性用・女性用の行に分けてからプラン名へ進み、「共通のまま」でもプラン名へ進む（女性の金額へ飛ばさない）。本文は「男性と女性で金額を分けられます。」。すでに男女別の行があるときは聞かない。費用の補足（任意）は金額のあとに置く
   * - 話す／言い直す（マイク）
     - 録音を始める。すでに値が入っている欄では言い直しになる
   * - 戻る（左矢印）
     - ひとつ前の欄に戻る。値は消さない。録音中でも押せ、いまの録音は捨てて戻った欄で録音を始める。戻り先が無いときは置かない。まとめてのときは使わない（出さない）
   * - スキップ（右矢印）
     - その欄を飛ばして次へ進み、その場で次の欄の録音を始める。録音中でも押せ、いまの録音は捨てる。費用の入口（プラン名の直前）では、先に男女別の質問を見る。まとめてのときは使わない（出さない）
   * - 「任意の項目も聞く」
     - 既定はオン。雨天時の方針・定員・申し込み期限も巡回に加える。オフにすると空欄の欄だけを聞く
   * - 「答えたら次へ」
     - 既定はオン。1 欄入れたら次の欄へ移り、そのまま録音を始める。オフなら同じ欄に留まり、録音も止める。まとめてのときは切り替えられない（出さない）
   * - 入力できる欄が尽きたとき
     - 必須がそろっていれば「必須項目の入力完了！」と「テーマを選び、チラシを作ると仕上がります。」を出す。スキップで必須を飛ばしていれば「必須の入力が残っています」と「ステップを開いて、残りを入れてください。」を出す。どちらも 5 秒後に音声モードを自動で終了する
   * - 画面の暗い部分
     - 操作できない。押すと抜け方をパネルに出す
   * - いま聞いている欄
     - その欄だけは触れる。音声で入れた値を手で直すときは、そのまま編集する

郵便番号を話すと、7 桁を受け取った時点で住所検索 API を 1 回だけ呼び、都道府県・市区町村・町域を入れます。
補完が終わってから次の欄を決めるため、埋まった都道府県を聞き直すことはありません（次は番地です）。
手入力でも 7 桁がそろうと 350ms 待って自動で引きます。同じコードを打ち直しても引き直しません。
検索の控えと実行中の問い合わせは 1 つにまとめてあるので（ ``src/modules/events/lib/postal-code-search.ts`` ）、
音声の補完と郵便番号欄が同じコードを引いても通信は 1 回です。
検索しているあいだは、パネルの質問を「住所を調べています」に替え、例と「いまの値」を隠します。
その間は主ボタンを出さず（押しても始められない的を残さない）、戻る・スキップは押せます。
0 件だったときと検索に失敗したときは進行を止めず、パネルに「住所を調べられませんでした。手で入力してください。」を 1 行出します。

フォーカスは見た目だけ
^^^^^^^^^^^^^^^^^^^^^^

音声モードは入力欄の DOM フォーカスを動かしません。枠を強調して、画面内へスクロールするだけです。

``type="date"`` と ``type="time"`` に実フォーカスを当てると、スマートフォンでは OS の日付・時刻ピッカーが開き、
画面を覆ってマイクの操作を妨げます。そのため、強調は ``data-voice-target`` 属性と CSS で行います。
読み上げには ``aria-live`` で欄の名前と誘導文を流します。

覆いと操作の制限
^^^^^^^^^^^^^^^^

音声モードの間は、画面全体を半透明の黒（ ``.voice-scrim`` ）で覆います。いま聞いている欄のまわりだけを
``clip-path`` でくり抜き、その内側だけ触れるようにします。くり抜きは当たり判定にも効くため、
他の欄・ステップの見出し・フッターは押せません。パネルは強調中の入力欄のすぐ下（欄の下端 + 8px）に置き、
右端は右下のマイクボタンの手前（ボタンの左 - 8px）で止めます。欄には重ねません。
パネルとマイクボタンは覆いより手前に出します。位置は欄の矩形とマイクボタンの左端から決めるため
（ ``src/modules/events/lib/voice/panel.ts`` ）、スクロールやキーボードで欄が動くたびに測り直します。
パネル（ ``.voice-panel`` ）には ``overscroll-behavior: contain`` を入れ、パネルの中のスクロールが後ろのページへ連鎖しないようにします。

くり抜きの穴は、欄の中心を画面の上から 35% の位置へ寄せる基準にします（下にパネルの居場所を残す）。パネルの上端を基準にすると、
パネルが欄の下へ動くたびに基準も動いて発振するためです。呼び出しでは ``spotlightFor`` に欄の矩形と画面の高さだけを渡し、
パネルの高さ（ ``reservedBottom`` ）は渡しません（引数と計算自体は残します）。

欄の矩形はスクロールやスマートフォンのキーボードで動くため、穴を測り直して追いかけます。
測るのは位置が動く合図（ ``scroll`` ・ ``scrollend`` ・ ``resize`` ・ ``ResizeObserver`` ・ ``data-voice-target`` の付け替え）があったときだけで、
毎フレームは回しません。対象の欄が見つからないとき（入力できる欄がすべて埋まったとき）は覆いを出しません。

ステップをまたぐと、欄はまだ描画されていません。描画を数十フレーム待ってから測りますが、
この待ち直しの最中も「位置が動く合図」は落とさずに受ける必要があります。
待ち直しのフレームで予約の控え（ ``frame`` ）を戻し忘れると、以降の合図がすべて捨てられ、
スクロール前の矩形のまま穴が止まります。対象は毎回 DOM から引き直し、控えた要素は使い回しません。
音声が開いたステップは音声モードのあいだ自動で畳まず、音声を抜けるまで聞いている欄を DOM に残して覆いの穴を保ちます。

穴の形は、欄の実測ではなく **高さを固定** して決めます（ ``src/modules/events/lib/voice/spotlight.ts`` ）。
欄の高さに合わせて測ると、スクロールで画面外にある欄の矩形のまま穴を空けてしまい、
画面幅や横幅の伸縮でずれます。固定した高さの穴を、スクロールで欄を画面の上から 35% の位置へ寄せます。

* 高さ … 単一行の入力欄に強調の枠と余白が収まる固定値（ ``SPOTLIGHT_HEIGHT`` ）。欄ごとに変えない
* 幅と左 … 縦スクロールでは動かないため、欄の実測に余白を足して伸縮させる
* 画面端 … 欄を中央まで寄せ切れないときは、高さを保ったまま穴だけが欄を追う（画面の内側に収める）

計算は DOM を読まない純ロジックなので、 ``tests/unit/voice-spotlight.test.ts`` で固定しています。

初回の案内も同じ仕組みでマイクボタンだけをくり抜きますが、穴は矩形ではなく **真円** にします
（ ``circleSpotlightClipPath`` ）。ボタンは角丸 999px の正方形なので、矩形で抜くと四隅に黒い角が残ります。
中心はボタンの中心、半径は半分の幅に 2px を足した値です。ボタンは縁を持たないので、2px は
切り抜きの縁とボタンの縁が重ならないための余白です。これを大きくするとボタンのまわりに黒い輪が見えます。
``path()`` の evenodd は書ける環境が限られるため、輪郭は 32 角形で近似します（半径 26px で角は 1px 未満）。

手で直すときは、いま聞いている欄をそのまま編集するか、``Esc`` かパネル右上の×で音声モードを抜けます。

録音の制限
^^^^^^^^^^

* 1 回の録音は最大 60 秒。超えると自動で止まる
* 送る音声は 5MB まで
* 音声モードに入った時点でマイクの許可を求める。許可を拒否されたら、その欄は手入力に戻る
* マイクの許可待ちのあいだに話すボタンを押し直しても、掴むマイクは 1 本だけ。開始の途中で音声モードを抜けたら、遅れて届いたマイクはその場で離す
* 録音は保存しない。文字にして返したら捨てる

API
---

``POST /api/v1/voice/transcriptions``
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

.. list-table::
   :header-rows: 1
   :widths: 24 76

   * - 項目
     - 内容
   * - 方式
     - ``multipart/form-data``
   * - ``audio``
     - 必須。音声ファイル。``audio/webm``、``audio/mp4``、``audio/ogg``、``audio/wav``、``audio/mpeg`` のいずれか。5MB まで
   * - ``field``
     - 任意。欄の名前（ ``title`` 、 ``scheduleDate`` など）。認識モデルに渡す短い文脈と語彙にだけ使う
   * - ``row``
     - 任意。2 件目以降の行の指定。0 始まりの整数で、イベントの行の最大数を超える値は捨てる
   * - ``title``
     - 任意。入力済みの催し名。固有名詞の当て字の手掛かりにだけ使う
   * - ``venueName``
     - 任意。入力済みの会場名。地名・建物名の当て字の手掛かりにだけ使う
   * - 成功
     - ``200`` と ``text/event-stream`` （下の「ストリーミング」）
   * - 失敗
     - ストリームを始める前だけ RFC 7807 の ``application/problem+json``

``title`` と ``venueName`` は入力済みのときだけ載せます。いま聞いている欄の現在値は送りません。
モデルがその値をそのまま返し、言い直しが効かなくなるためです。

ストリーミング
^^^^^^^^^^^^^^

検証を通ると、``text/event-stream`` で次の 3 種類のイベントを返します。
``event:`` の名前と ``data:`` の JSON が対応します。

.. list-table::
   :header-rows: 1
   :widths: 16 34 50

   * - イベント
     - ``data``
     - 意味
   * - ``delta``
     - ``{"text": "12月"}``
     - 認識できた分の増分。届くたびに途中経過を更新する
   * - ``done``
     - ``{"text": "12月5日", "model": "gpt-transcribe"}``
     - 全文と、実際に使ったモデル。控えのモデルへ落ちたときはその名前になる
   * - ``error``
     - ``{"error": "TRANSCRIBE_FAILED", "detail": "…"}``
     - ストリーム開始後の失敗。ステータスは 200 のまま

* 最初の ``delta`` まで 10 秒、以降は ``delta`` の間隔が 15 秒を超えたら打ち切ります
* 画面が切れたら、上流の読み取りも止めます
* 応答をためるプロキシを通すと ``delta`` が届かず、最後にまとめて返ることがあります。
  そのときは完了後の文字だけを受け取り、途中経過は出ません（応答が JSON なら従来どおり ``text`` を読みます）
* 上流が ``stream`` を知らないとき（400 など）は、同じ内容を ``stream`` 無しで 1 度だけやり直します

ストリームを始める前の失敗（形式・空・5MB・回数の上限・``TRANSCRIBE_DISABLED`` ）は、
従来どおり ``application/problem+json`` で返します。開始後はステータスを変えられないため、
``error`` イベントの ``error`` と ``detail`` だけを返します。

.. list-table::
   :header-rows: 1
   :widths: 14 30 56

   * - 状態
     - ``error``
     - 意味と画面の動き
   * - ``400``
     - ``-``
     - 音声が空、または本文を読めない。もう一度録音する
   * - ``413``
     - ``-``
     - 5MB を超えた。短く話す
   * - ``415``
     - ``-``
     - 音声以外の形式。ブラウザの録音形式を確認する
   * - ``422``
     - ``TRANSCRIBE_EMPTY`` / ``TRANSCRIBE_UNSUPPORTED``
     - 聞き取れなかった、句読点だけで空になった、または上流が形式を受け付けない。もう一度話すか手で入力する
   * - ``422``
     - ``TRANSCRIBE_CONTEXT_INVALID``
     - モデルが使えない、または ``prompt`` / ``keywords`` を上流が受け付けない。モデルが使えないだけなら控えのモデルで 1 度だけ試し、それでもだめなときに返る。設定を見直す
   * - ``429``
     - ``RATE_LIMITED`` / ``TRANSCRIBE_BUSY``
     - 回数の上限、または上流が混雑。 ``Retry-After`` に従う
   * - ``502``
     - ``TRANSCRIBE_MISCONFIGURED`` / ``TRANSCRIBE_FAILED``
     - 鍵の設定不備、または上流に繋がらない。手で入力する
   * - ``503``
     - ``TRANSCRIBE_DISABLED``
     - ``OPENAI_API_KEY`` が未設定。手で入力する

上限に当たると ``429`` に ``Retry-After`` と ``X-RateLimit-Limit`` 、 ``X-RateLimit-Remaining`` が付きます。
本文には ``limitLabel`` 、 ``attemptLimit`` 、 ``windowSeconds`` 、 ``retryAfterSeconds`` 、 ``retryAt`` が入ります。

まとめて話す（サーバー側）
^^^^^^^^^^^^^^^^^^^^^^^^^^

``POST /api/v1/voice/utterances``

1 回の発話から複数の欄を埋めます。文字起こしは 1 回だけで、割当はサーバー側で決めます。
対象はまだ空の欄だけです。入力済みの欄は候補から外すので、まとめて話しても手で入れた値を静かに上書きしません。
画面が「話す順」のマスと質問を作るときも同じ一覧（ ``src/modules/events/lib/voice/batch-guide.ts`` の ``batchTargets`` ）から
``batchPlan`` を組み、案内の順に話せばそのとおりに割り当たります。

.. list-table::
   :header-rows: 1
   :widths: 24 76

   * - 項目
     - 内容
   * - 方式
     - ``multipart/form-data``
   * - ``audio``
     - 必須。音声ファイル。5MB まで
   * - ``value``
     - 必須。いまのフォームの値（JSON）。``schedules`` と ``pricePlans`` は 1 件以上
   * - ``scope``
     - 任意。巡回の指定（JSON）。``showOrganizerName`` 、 ``includeOptional`` 、 ``touched``
   * - 成功
     - ``200`` と ``text/event-stream``
   * - 失敗
     - ストリームを始める前は RFC 7807 の ``application/problem+json``

応答は**ストリーム**です。文字起こしの増分が届くたびに、言い終わった節だけを決定的に
割り当て、読めたマスを ``cell`` で先に返します。値は ``done`` にまとめて入れるので、
途中の値が確定値として画面へ出ることはありません。

.. code-block:: text

   event: delta
   data: {"text":"12月5日、"}

   event: cell
   data: {"slotId":"scheduleDate:0"}

   event: done
   data: {"text":"12月5日、18時から20時、渋谷ホール","assignments":[…],"unassigned":[…],"model":"gpt-transcribe"}

``delta`` は聞き取れた文字の増分、 ``cell`` は読めたマス（ ``slotId`` だけ。値は無い）、
``done`` は全文・割当・未割当・モデルです。途中で失敗したら ``error`` に ``error`` と ``detail`` を入れます
（本文は流れ始めているため、ステータスは 200 のまま）。

``cell`` は「区切りで閉じた節」だけを対象にします。最後の区切りより後ろは言いかけなので捨てるため
（ ``utterance.ts`` の ``terminatedPrefix`` ）、「12月」まで聞こえた時点で日付として確定しません。

``slotId`` は ``欄のキー:行`` です（ ``scheduleDate:0`` 、 ``planAmount:1`` ）。``value`` は確認に出す
読みやすい値（金額は数値、日付は ``YYYY-MM-DD`` ）で、``patch`` がフォームへ当てる差分です。
``unassigned`` はどの欄にも当たらなかった節です。``model`` は実際に使った認識モデルです。

割当の手順は決定的です（ ``src/modules/events/lib/voice/utterance.ts`` ）。

1. 読点・句点・カンマ・終止点・話し言葉の「で」「と」「や」・空白で節に分ける
2. 形の閉じた欄（日付・時刻・金額・定員・郵便番号・都道府県・雨天・期限）を巡回順に当て、一致した節を消費する。同じ節を 2 つの欄に使わない。対象は空欄だけ（ ``batchTargets`` ）
3. 自由文の欄は、その欄の語彙が節に現れるときだけ受け取る
4. ``scheduleStart`` が範囲（「18時から20時」）を返したら、同じ行の ``scheduleEnd`` は割当済みにする

決定的に割り当てられなかった節だけを、LLM に「どの節がどの欄か」として尋ねます（ ``batch.ts`` ）。
LLM が返すのは ``slotId`` と節の文字列だけで、値は作りません。返ってきた節は必ずその欄の
``parse`` に通し、読めないときは捨てます。存在しない ``slotId`` 、未割当でない節、重複した割当も捨てます。
LLM が失敗しても、決定的な割当だけは返ります。

モデルは ``VOICE_BATCH_MODEL`` （既定 ``gpt-4.1-mini`` ）です。``json_schema`` を返せないモデルでは
``json_object`` で 1 度だけ試します。``VOICE_BATCH_LLM=0`` にすると LLM を呼ばず、決定的な割当だけになります。

回数の上限は ``/api/v1/voice/transcriptions`` と共有します（1 回で 1 カウント）。
モック（ ``VOICE_TRANSCRIBE_MOCK=1`` ）では、巡回する空欄の入力例を「、」でつないだ 1 文を返します。

導入手順
--------

1. OpenAI の API キーを用意する
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

`OpenAI Platform <https://platform.openai.com/api-keys>`_ で API キーを作ります。
音声認識は ``gpt-transcribe`` を使います。モデル名は環境変数で差し替えられます。

2. 環境変数を置く
^^^^^^^^^^^^^^^^^

``.env`` （ローカル）または配信先のシークレットに、次を設定します。

.. code-block:: ini

   OPENAI_API_KEY="sk-..."
   VOICE_TRANSCRIBE_MODEL=""
   VOICE_TRANSCRIBE_FALLBACK_MODEL=""
   VOICE_BATCH_MODEL=""
   VOICE_BATCH_LLM=1

``VOICE_TRANSCRIBE_MODEL`` が空なら ``gpt-transcribe`` を使います。
``VOICE_TRANSCRIBE_FALLBACK_MODEL`` が空なら ``gpt-4o-mini-transcribe`` 、
``VOICE_BATCH_MODEL`` が空なら ``gpt-4.1-mini`` を使います。``VOICE_BATCH_LLM`` は ``0`` のときだけ無効です。
``OPENAI_API_KEY`` が空のとき、画面のマイクボタンは押せますが、録音を送った時点で
「音声入力は現在利用できません」と出て、手入力に戻ります。アプリは起動したままです。

.. list-table::
   :header-rows: 1
   :widths: 40 22 38

   * - 名前
     - 既定
     - 役割
   * - ``OPENAI_API_KEY``
     - なし
     - 音声認識の鍵。未設定なら音声入力は無効
   * - ``VOICE_TRANSCRIBE_MODEL``
     - ``gpt-transcribe``
     - 認識モデル
   * - ``VOICE_TRANSCRIBE_FALLBACK_MODEL``
     - ``gpt-4o-mini-transcribe``
     - モデルが使えない（400/404）ときに 1 度だけ試す控え。控えでは ``keywords`` を送らない
   * - ``VOICE_TRANSCRIBE_LANGUAGE``
     - ``ja``
     - 認識に使う言語。日本語を明示して、英語へ流れるのを抑える
   * - ``VOICE_TRANSCRIBE_LIMIT``
     - ``40``
     - 接続元（IP）ごとの回数。窓の中で数える。まとめて話すときも 1 回で 1 と数える
   * - ``VOICE_TRANSCRIBE_WINDOW_MINUTES``
     - ``60``
     - 回数を数える窓（分）
   * - ``VOICE_TRANSCRIBE_MOCK``
     - ``0``
     - ``1`` なら OpenAI を呼ばず、欄の入力例を認識結果にする（開発用）
   * - ``VOICE_BATCH_MODEL``
     - ``gpt-4.1-mini``
     - まとめて話すときの割当に使う LLM
   * - ``VOICE_BATCH_LLM``
     - 有効
     - ``0`` なら LLM を使わず、決定的な割当だけにする

3. 課金と上限を決める
^^^^^^^^^^^^^^^^^^^^^

音声認識は従量課金です。執筆時点の公開価格は 1 分あたり約 0.003 ドルですが、**必ず公式の料金ページで確認してください**。
1 欄あたり 3〜8 秒とすると、1 件（15 欄前後）でおよそ 1〜2 分です。

既定の上限 ``40 回 / 1 時間 / IP`` は、1 人が 2 件ぶん作れる程度です。
大人数が同時に使う環境では ``VOICE_TRANSCRIBE_LIMIT`` を上げてください。

数えるのはプロセスのメモリ上です。インスタンスを増やすと合計の上限も増えるため、
厳密に止めたい場合は DB か共有ストアへ移す必要があります（未実装）。

4. 動作を確かめる
^^^^^^^^^^^^^^^^^

.. code-block:: powershell

   npm run dev

``/organizer/events/new`` を開き、右下のマイクボタンを押します。
「催しの名前」から順に強調されるので、「忘年会」と話して赤い停止ボタン（四角）を押します。
値が入って次の欄へ進めば成功です。

開発ツールの Network で ``/api/v1/voice/transcriptions`` が ``200`` を返すことも確認できます。

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - 症状
     - 見るところ
   * - マイクボタンを押しても録音が始まらない
     - ブラウザのマイク許可。``https`` または ``localhost`` で開いているか。マイクの無い PC なら ``VOICE_TRANSCRIBE_MOCK=1`` で確かめる（下の「課金せずに試す」）
   * - 「音声入力は現在利用できません」
     - ``OPENAI_API_KEY`` が空。サーバーを再起動したか
   * - 「音声認識の設定が正しくありません」
     - 鍵が無効、または音声認識の権限が無い
   * - 値が入らない
     - 画面に出た「読めませんでした」の文言。欄に対して言い方が合っているか
   * - すぐ上限になる
     - ``VOICE_TRANSCRIBE_LIMIT`` 。開発中は大きめにする

5. 課金せずに試す（モック）
^^^^^^^^^^^^^^^^^^^^^^^^^^^

鍵を用意せず、課金もせずに画面の流れを確かめたいときは ``VOICE_TRANSCRIBE_MOCK=1`` を使います。

.. code-block:: ini

   VOICE_TRANSCRIBE_MOCK=1

有効にすると、録音と認識の問い合わせをまとめて差し替えます。マイクを掴まず、OpenAI へも送りません。
画面は開いたときに ``GET /api/v1/voice/transcriptions`` でモックの可否を 1 度だけ聞き
（返事が遅ければ 1.5 秒で打ち切る）、
疑似の録音（1.2 秒の「録音中」）のあと、いま聞いている欄の入力例（ ``fields.ts`` の ``example`` 。
「12月5日」「3000円」など）を確認に置きます。入力例は ``parse.ts`` が読める形で
書いてあるため、確認すると聞き直しにならず次の欄へ進みます。

* マイクも許可も要りません。録音デバイスの無い PC でも、確認から自動遷移までを最後まで確かめられます
* 話すボタンを押すと、待たずにその場で文字化へ移ります。待つ長さは ``VoiceInputDock.tsx`` の ``MOCK_RECORDING_MS`` と ``MOCK_TRANSCRIBE_MS`` です
* ``OPENAI_API_KEY`` は空のままで動きます。503 の ``TRANSCRIBE_DISABLED`` は出ません
* 回数の上限を数えません。開発中に ``429`` で止まらないようにするためです
* 確認の流れは実の経路と同じように出ます。録音だけを差し替え、画面の流れは変えないためです
* 可否の返事が 1.5 秒を超えたら打ち切ります。打ち切ったあとは実の録音に倒れるため、疑似の録音には入りません（本番は常に打ち切り側に倒れます）
* ``NODE_ENV=production`` では常に無効です。``next build`` と ``next start`` が該当します
* 設定が効いているか分からないときは、サーバーのログを見てください。``/api/v1/voice/transcriptions`` を初めて読み込んだ時点で、次のどちらかが 1 度だけ出ます

.. code-block:: text

   [voice] モックが有効です（VOICE_TRANSCRIBE_MOCK=1）。OpenAI へは送らず、欄の入力例を返します。
   [voice] OPENAI_API_KEY が未設定です。音声入力を送ると 503（TRANSCRIBE_DISABLED）になります。

モックの付け忘れと切り忘れの両方に気づけるようにするためです。本番では出ません。

確かめられるのは、疑似の録音から確認、値の決定、フォームへの反映、ステップの自動展開、
次の欄への巡回までです。実の録音・送信と認識の精度だけは対象外です
（実の経路は ``VOICE_TRANSCRIBE_MOCK=0`` で、マイクのある端末で確かめます）。

モデルや提供元を変える
----------------------

音声認識の差し替えは ``openai.ts`` の 1 ファイルで済みます（まとめて話すときの割当は ``batch.ts`` の別の呼び出しです）。

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - ファイル
     - 役割
   * - ``src/modules/events/lib/voice/openai.ts``
     - OpenAI への送信とエラーの対応付け
   * - ``src/modules/events/lib/voice/parse.ts``
     - 認識結果をフォームの値へ変える規則。ここは提供元に依存しない
   * - ``src/modules/events/lib/voice/fields.ts``
     - 欄の並び、空欄の判定、次に聞く欄、 ``keywords`` に渡す語彙

``parse.ts`` と ``fields.ts`` は文字だけを受け取るので、提供元を変えても触りません。
``openai.ts`` の ``transcribeWithOpenAi`` を同じ形（文字を返す）で置き換えれば、
API ルートと画面はそのまま動きます。

.. list-table::
   :header-rows: 1
   :widths: 26 74

   * - 提供元
     - 変えるところ
   * - OpenAI の別モデル
     - ``VOICE_TRANSCRIBE_MODEL`` を変える。``whisper-1`` を指定すると ``language`` だけを送る旧系統になる
   * - 何も呼ばない（モック）
     - ``VOICE_TRANSCRIBE_MOCK=1`` 。``openai.ts`` は鍵より先に ``mockTranscript`` を返す
   * - 自前のサーバー（Whisper など）
     - ``transcribeWithOpenAi`` の ``fetch`` 先を自前の URL にし、``OPENAI_API_KEY`` の代わりの鍵を読む。``.env.example`` とこのページを更新する
   * - 端末内の認識（WASM）
     - ``src/modules/events/lib/voice/transcribe.ts`` を、録音を送らずに端末で文字へする実装に差し替える。API ルートは不要になる

モデルで変わるパラメータ
^^^^^^^^^^^^^^^^^^^^^^^^

送るパラメータはモデルの系統で変わります（ ``openai.ts`` の ``voiceModelFamily`` ）。

.. list-table::
   :header-rows: 1
   :widths: 34 66

   * - 系統
     - 送るもの
   * - ``gpt-transcribe`` （既定）
     - ``languages[]=ja`` と ``keywords[]`` 。``language`` は送らない（併用できないため）
   * - ``gpt-4o-transcribe*`` / ``whisper-1``
     - ``language=ja`` だけ。``keywords`` と ``languages`` は送らない

``prompt`` は指示文ではなく短い文脈です（例:「イベント作成フォームの「開催日」を話しています。」）。
「〜してください」のような指示や、数字の表記を強制する文は入れません。語彙は ``keywords`` へ分けます。

``keywords`` には次の制約があります。上流は 1 つでも反するとリクエスト全体を拒否するため、
送る前に整えます。

* 1 語を 1 行にして送る。``<`` ``>`` と改行を含む語は落とす
* 欄ごとに 20 語まで、1 語は 60 文字まで。超えた分は落とす
* 入力済みの催し名と会場名を先頭に置く。いま聞いている欄の現在値は入れない

``gpt-transcribe`` がアカウントで使えないとき（400/404）は、``VOICE_TRANSCRIBE_FALLBACK_MODEL``
（既定 ``gpt-4o-mini-transcribe`` ）で 1 度だけ試します。控えは旧系統のことが多いため、語彙は渡さず
``language`` だけで送ります。それでも通らなければ 422 ``TRANSCRIBE_CONTEXT_INVALID`` を返します。
応答の ``model`` は、実際に使ったモデル名です。

プライバシー
------------

* 録音はアプリのサーバーを経由して OpenAI へ送ります。端末内で完結しません
* 入力済みの催し名と会場名は、当て字の手掛かりとして音声と一緒に送ります。いま聞いている欄の現在値は送りません
* 音声も認識結果も保存しません。DB に列はありません。まとめて話すときも同じです
* 音声は認識のためだけに使い、学習には使いません（OpenAI の API 利用規約に従う）
* まとめて話すときの割当の推定で LLM へ送るのは、未割当の節と欄の候補（ ``slotId`` と欄の名前）だけです。
  音声・フォームの値・入力済みの個人情報は送りません。値は LLM に作らせず、 ``parse.ts`` が作ります。
  ``VOICE_BATCH_LLM=0`` で LLM の呼び出し自体を止められます
* 右下のマイクボタンを押した時点でマイクを開きます。それ以外で許可を求めることはありません

制約
----

* 開催日時と費用の行も音声で埋められる。2 件目以降の行は、分岐の質問で行を足すか「日時を追加」「プランを追加」で手入力してから、行ごとに聞く
* 男女別の費用も音声で埋められる。費用の入口（プラン名の直前）の分岐の質問で切り替えるか、手で切り替えてから女性用の金額を聞く
* 音声認識の文字が欄の意味に合わないときは「読めませんでした」と出して値を変えない。勝手に埋めない
* まとめて話すときは、節の切れ目と欄の語彙で割り当てる。当たらなかった節は ``unassigned`` で返り、埋めない
* まとめて話すときのマスは、録音を止めたあとに届く文字起こしの増分で塗る。録音中そのものは塗れない。
  録音を区切って送れば塗れるが、認識の回数（課金と回数の上限）が増えるため、いまは止めてから 1 回だけ送る
* 途中経過（ ``delta`` ）は、応答をためるプロキシを通ると届かない。そのときは完了後の文字だけで確認する
* 回数の上限はプロセスのメモリ上。インスタンスごとに数える
* 編集画面（ ``/organizer/events/[id]/edit`` ）は対象外
